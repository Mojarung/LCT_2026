# green

Сервис автопроектирования озеленения улиц для кейса ДПиООС (ЛЦТ 2026): DXF или DWG с подосновой и сетями -> ограничения по нормам -> план посадок на отдельных слоях `GREEN_*` -> DXF и файл объяснений со ссылками на правила и пункты НПА. Исходные слои не меняются, это проверяется на каждом прогоне.

```bash
uv sync
uv run green run путь/к/файлу.dxf --profile strict
uv run green run путь/к/файлу.dxf --inventory перечётка.xls   # существующие деревья в квотах
uv run green run генплан.dxf сети.dxf покрытия.dxf            # комплект DXF склеивается в один чертёж
uv run green run путь/к/файлу.dxf --profile barriers          # с прикорневыми барьерами (СП 42, табл. 9.1, прим. 5)
uv run green serve                  # OpenAPI: http://127.0.0.1:8000/docs
docker compose up --build           # то же в контейнере, API на :8000
```

Вид для каждой посадки подбирается сервисом: жёсткие фильтры по нормам (369-ПП, 743-ПП п. 3.6.18, отступы по роду, крона шире 5 м, высота под ВЛ) и по справочнику (морозостойкость, реагенты), затем оценка пригодности в процентах и назначение с жёсткими квотами разнообразия 10-20-30. Перечётная ведомость через `--inventory` добавляет в квоты уже растущие деревья. База видов — [config/species.yaml](config/species.yaml), её описание — [docs/species.md](docs/species.md).

Артефакты прогона: `result.dxf`, `plan.json`, `interpretations.csv` и `.json`, `assortment.json` и `assortment_shrubs.json` (состав плана: доли, разнообразие, сезонность), `planting_schedule.csv` (ведомость: количества, размер кома, площадь под посадочные ямы), `zones.geojson`, `run_manifest.json`, `verify.json`, `layers_report.json`.

Линтеры и тесты: `uv run ruff check src tests`, `uv run ruff format --check src tests`, `uv run ty check src`, `uv run lint-imports`, `uv run pytest`.

Подробности: [docs/architecture.md](docs/architecture.md), алгоритм по шагам: [docs/algorithm.md](docs/algorithm.md), база видов: [docs/species.md](docs/species.md), разбор ресерча: [docs/research-review.md](docs/research-review.md), требования к посадке по актам заказчика: [docs/requirements/planting-requirements.md](docs/requirements/planting-requirements.md).

## Журнал правок

Каждая запись: что сделано, почему, чем проверено. Подробный ход с командами лежит в заметке по ссылке.

### 18.09.2026

1. **Ответы заказчика разобраны** ([notes/15](docs/notes/15-organizers-qa.md)). 35 вопросов сессии сопоставлены с сервисом: что совпало, что сделано, что в плане, какие вопросы вернуть заказчику.
2. **Охранная зона газопровода отключена.** Заказчик ответил, что охранные зоны поверх нормативных отступов не применяются (вопрос 8). Новый параметр профиля `disabled_rules`, в профилях отключено `R-GASZONE-TREE-001`, отступ 1,5 м по табл. 9.1 СП 42 действует. Проверка: `tests/test_disabled_rules.py`; Берзарина 306 мест вместо 301, 282 посадки.
3. **Найдена табл. В.6 МГСН 1.02-02** (виды по категориям насаждений). В аллее Берзарина 26 из 54 посадок оказались видом с отметкой «-» для улиц. Записано как требование F10.
4. **Колючие растения не ближе 2 м от пешеходных путей** (СП 82.13330.2016 п. 9.22). У правила расстояния появилось поле `traits`, четыре правила `R-THORN*` с дословной цитатой. Проверка: тест `test_thorny_plants_keep_two_metres_from_pedestrian_ways`; на Берзарина боярышников ближе 2 м к тротуару было 7 из 28, стало 0, посадок по-прежнему 280 (повтор подбора по прогону `berzarina_norms`).
5. **Категории насаждений по табл. В.6 МГСН 1.02-02** ([notes/16](docs/notes/16-categories-shrubs-barriers.md), раздел 1). Поле `categories` у 36 видов, параметр `planting_category`, правило `R-MGSN-CATEGORY-001`, фактор оценки `category`. Берёза больше не запрещается как аллерген: её рекомендуют 515-ПП и МГСН. Проверка: в аллее Берзарина лоха (отметка «-» для улиц) было 26 посадок, стало 0.
6. **Квоты кустарников** (раздел 2 той же заметки). Доли для кустарников вынесены в параметры проекта, кустарники из перечётки в квоты не входят. Проверка: на Берзарина все 76 мест, пустых из-за квот деревьев, заняты группами, 615 кустарников; до правки было 0.
7. **Профиль `barriers`: прикорневые барьеры** (раздел 3). СП 42 табл. 9.1 прим. 5: дерево допускается в 0,5-1 м от сетей и борта с барьером. Исход проверки `barrier`, слой `GREEN_TREES_BARRIER`, основание `R-BARRIER-ROOT-001`. Проверка: `tests/test_root_barriers.py`; Берзарина 350 деревьев вместо 230 (у проектировщика 318), 131 с барьером, квоты и целостность в порядке.
8. **Приём комплекта из нескольких DXF** ([notes/17](docs/notes/17-multi-dxf-input.md)). Заказчик подаёт генплан и геоподоснову разными файлами. `green run a.dxf b.dxf ...`, поле `extra` в API, склейка через `ezdxf.xref`. Проверка: `tests/test_multi_dxf.py`; реальный комплект заказа 25_03117 из четырёх DWG одним вызовом: 308 969 сущностей, 3 542 дерева, целостность 507 532 сущностей, 323 с.
9. **Ведомость посадочного материала** `planting_schedule.csv`. Заказчик назвал ошибки в объёмах второй причиной возврата проектов (вопрос 14). Графы повторяют ведомость проектировщика из датасета (Лодочная): количество, стандарт, размер кома, площадь под посадочные ямы, итоги по разделам. Размеры ям по 743-ПП табл. 3.3.1, стандарт саженца по 515-ПП, раздел 4 ([notes/18](docs/notes/18-planting-schedule.md)). Проверка: `tests/test_schedule.py`; ведомость Берзарина: 230 деревьев и 972,98 м2 под ямы, 615 кустарников и 483,01 м2.
10. **Проверка комплекта на совпадение по месту** (раздел 3 той же заметки). Файл комплекта, габариты которого перекрываются с основой меньше чем наполовину, называется в предупреждениях: так выглядел несогласованный набор `sample_*.dxf`. Проверка: `test_kit_from_different_places_is_reported`.
