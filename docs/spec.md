# Требования кейса и границы решения

Первичный источник — 13-страничное ТЗ ДПиООС 2026 (`../../3. Департамент природопользования и охраны окружающей среды (1).pdf`, локально вне Git). Этот файл сопоставляет требования ТЗ с **текущим `green`** на 16.09.2026; он не предлагает параллельную архитектуру. Первоначальный проектный черновик Альберта сохранён в истории Git (`231e547`, `9ad8269`). Реализация описана в [algorithm.md](algorithm.md), незакрытые шаги — в [plan.md](plan.md).

| Требование ТЗ | Наличие сейчас | Оставшийся разрыв / источник проверки |
|---|---|---|
| Пространственные входы: геоподоснова, коммуникации, кадастр, зонирование, среда | DXF/DWG reader, классы сетей и городских объектов; один файл на вход | Автоматический сбор пакета eTransmit/XREF и отдельные кадастровые/зональные слои пока отсутствуют. [Данные](notes/08-dataset-map.md), [план](plan.md) |
| Карта «где можно сажать» с нормами и условиями участка | `zones.py`, `constraints.py`, слои `GREEN_ZONE_*` | Материал `SurfaceMap` эвристический; зона проверяет центр ячейки, не доказанный контур лунки, грунт и проход. [Разбор покрытия](notes/06-surface-map.md) |
| Рекомендации и автоматический план деревьев и кустарников | Аллея и сетка по газону; профиль одного вида за прогон | Группы, кустарники как полноценная стратегия, разный ассортимент и контекст участка неполны. [План](plan.md) |
| Не менять исходные слои; экспортировать отдельные слои DXF | Writer добавляет только `GREEN_*`; checker сравнивает экспортируемые DXF-сущности | Неэкспортируемые `REGION` и содержательная потеря при DWG→DXF вне этой гарантии; открытие вторым CAD-просмотрщиком не проверено. [Целостность](algorithm.md#11-проверка-целостности) |
| Перенастраивать и корректировать решение | Профили и `--set` / API overrides позволяют повторный прогон | Перемещение и закрепление посадок в редакторе не реализованы; по ТЗ UI желателен, но не блокирующий |
| Для каждой посадки и отказа объяснение с актом и пунктом | Трасса правил, XDATA и файлы интерпретаций | Статусы и редакции нормативных текстов требуют дополнительной проверки; [сверка норм](notes/07-norms.md) |
| Работа в МосТех.ОС/Linux, Docker, OpenAPI при API | Dockerfile, compose, FastAPI/OpenAPI | Проверка на целевом стенде и в nanoCAD/QCAD под Linux ещё нужна. [План](plan.md) |
| Фото «после» как бонус | Не реализовано | Требует привязки фото к окончательному DXF; не должно влиять на нормативный вердикт |
| Документация, схема алгоритма, презентация и короткое демо в CAD | README, описание алгоритма и схема есть | Подготовить инструкцию под целевую ОС, презентацию 10–20 слайдов и демо 4–10 минут с проверкой DXF в CAD; [план](plan.md) |

Успех измеряется отдельно по допустимости, полноте данных, качеству композиции, объяснимости, сохранности DXF и времени. Число сгенерированных деревьев или близость к эталонным точкам не заменяет проверку посадочной площадки. Наблюдения по пилоту и ограничения измерений лежат в [notes/04-issues-and-fixes.md](notes/04-issues-and-fixes.md) и [notes/09-berzarina-layers-and-offsets.md](notes/09-berzarina-layers-and-offsets.md).
