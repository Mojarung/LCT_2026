# Сценарий демонстрации (4-10 минут)

Формат финала по ТЗ: живой прогон, проверка DXF в CAD под Linux, файлы интерпретаций. Ниже сценарий с командами и тем, что показывать на экране. Улица: Берзарина (генплан 206 860 сущностей, перечётка 855 строк, посадочный план проектировщика). Все числа ниже взяты из прогонов 18.09.2026 (`docs/notes/18`, `21`, `23`, `24`).

## До начала

- Контейнер поднят: `docker compose up -d`, `curl localhost:8000/api/v1/health`.
- Прогоны сделаны заранее (Берзарина считается 150 с): `out/demo/berzarina` (`green run`) и `out/demo/audit` (`green audit`). Живой прогон на показе идёт на маленьком чертеже, чтобы уложиться в минуту, большой открывается готовым.
- В nanoCAD, QCAD или LibreCAD открыты две вкладки: исходный `gp.dxf` и `result.dxf`. В LibreCAD подписи посадок не видны (в его штриховом шрифте нет кириллицы), открытый чертёж надо вписать командой `za`, а полный генплан на 76 МБ он не открывает и за семь минут - в нём показывать фрагмент; проверенный под Linux вариант - образ `docker/cadcheck/` (`docs/deploy.md`).

## 1. Вход (1 мин)

Показать исходный DXF: топоплан Мосгеотреста, сети, здания, борта. Сказать, что сервис принимает DXF или DWG и комплект из нескольких файлов (генплан + сети + покрытия), DWG конвертируется внутри.

```bash
uv run green inspect dataset/берзарина/gp.dxf | head -60
```

На экране: слои и их классы (`layers_report`), 76 правил, предупреждения читателя (ремонт строк LibreDWG, единицы чертежа).

## 2. Живой прогон (2 мин)

```bash
uv run green run dataset/малая_улица.dxf --profile strict --set spacing_m=6 --out out/demo/live
```

Пока идёт: рассказать конвейер (`docs/algorithm.md`): классификация слоёв по `layer_map.yaml`, диаметры из подписей, карта покрытий (посадки только на грунте), кандидаты (аллея вдоль борта, сетка по газону), векторная проверка 46 правил расстояний, жёсткие квоты 10-20-30 при подборе видов, группы кустарников на местах, пустых из-за квот.

Показать сводку в консоли: посадок, отказов, `integrity_ok: true`, время по стадиям.

## 3. Результат в CAD (2 мин)

Открыть `result.dxf`. Показать:

- слои `GREEN_TREES`, `GREEN_SHRUBS`, `GREEN_REJECT`, `GREEN_ZONE_ALLOWED`; исходные слои не тронуты;
- у посадки атрибуты `NUM`, `SPECIES`, `NPA` (правила, по которым она стоит ближе всего к норме), XDATA `LCT_GREEN`;
- легенду с пунктами актов (MTEXT на `GREEN_LABELS`).

Параллельно `verify.json`: `206860 из 206860 без изменений, changed: [], added_outside_result_layers: []`. Это доказательство, а не обещание: отпечаток каждой исходной сущности до и после.

## 4. Интерпретируемость (2 мин)

Открыть `interpretations.csv` (или `plan.json`). Одна посадка (Берзарина, `out/check/berzarina_load`): «Посадка №3, Боярышник обыкновенный (Crataegus laevigata), аллея вдоль борта: посадка допускается. Ближайшие ограничения: до бортового камня 2.00 м >= 2.00 м (R-CURB-TREE-001: СП 42.13330.2016, п. 9.6, табл. 9.1: край проезжей части улиц ...; 743-ПП, п. 3.6.3, табл. 3.6.1; 623-ПП (МГСН 1.02-02), п. 4.2.4); до канализации до наружной стенки 2.44 м >= 1.50 м (R-SEWER-TREE-001: ...)». Один отказ: «Отказ №1: посадка запрещена. Причины: до наружной стены здания 3.37 м < 5.00 м (R-BLD-TREE-001: ...)». Подбор вида: почему боярышник, а не лох (МГСН табл. В.6, отметка «-» для улиц), квоты, оценка пригодности.

`planting_schedule.csv`: ведомость с размерами кома и площадью под ямы (743-ПП табл. 3.3.1), 230 деревьев, 972,98 м2.

## 5. Нормоконтроль (1-2 мин)

```bash
uv run green audit "dataset/берзарина/Посадочный план.dxf" --plantings "^0?6_+ДП_.+_план$" --out out/demo/audit
```

Показать `audit.md`: у плана проектировщика 391 посадка из 554 с нарушением отступов (785 нарушений: силовой кабель 159, борт 104, опоры 77, водопровод 71), у плана сервиса 0 из 860. Открыть `audit.dxf`: красные отметки на `GREEN_AUDIT_VIOLATION` с номерами правил. Сказать, что часть замечаний снимает проектировщик (демонтируемый борт, сети в футлярах), но список с координатами, пунктом акта и недобором в метрах у него теперь есть.

## 6. Веб-интерфейс (2 мин)

`http://localhost:8000/` - то же, что делали командой, но глазами и без консоли.

1. Улица из списка пилотного проекта - первое, что видит человек на странице: девятнадцать
   улиц с готовыми комплектами подосновы и сетей, выбор в один клик. Для показа берём
   Камчатскую (39,5 МБ, полторы минуты): пока считается, внизу полоса хода с этапом,
   процентами и остатком, а чертёж появляется
   на карте, как только прочитан (около 40-й секунды), и его можно разглядывать - слои,
   масштаб, разворот вдоль улицы. По готовности посадки ложатся на тот же вид.
   Если датасет на стенде не смонтирован, на том же месте появляется встроенный фрагмент
   Берзарина (300 x 140 м, около двух тысяч посадок вместе с кустарником, около минуты) -
   показывать есть что в любом случае.
2. Карта плана на подоснове: сети по цветам, здания, граница работ, посадки кругом кроны.
   Вид развёрнут вдоль улицы, в углу стрелка севера и масштабная линейка; кнопка «по улице /
   по северу» возвращает ориентацию чертежа.
3. **Клик по дереву** - в панели вид, норма с наименьшим запасом и пункт акта с дословной
   цитатой. Это и есть требование интерпретируемости, предъявленное за десять секунд.
   То же самое доступно с клавиатуры: Tab на карту, стрелки - переход по посадкам вдоль
   улицы, Enter центрирует.
4. Клик по строке в составе плана подсвечивает этот вид на карте: видно, как разложены
   тринадцать видов и где сработали квоты разнообразия.
5. Включить «Правку плана», потянуть дерево к водопроводу: кружок краснеет **до** того, как
   отпустили кнопку. Отпустить - посадка уходит в отказы с названием нарушенной нормы.
   Без мыши то же самое: Alt со стрелками сдвигает выбранную посадку на полметра, а кнопка
   «Указать новое место на карте» в панели переносит её в точку следующего клика.
6. «Пересобрать DXF» - правка попадает в `result.dxf` и во все объяснения, целостность
   исходных слоёв проверяется заново.

Сказать вслух: интернета странице не нужно, внешних запросов она не делает.

## 7. API (1 мин)

`http://localhost:8000/docs`: `POST /api/v1/runs` с файлом и профилем, `GET /runs/{id}`, артефакты. Ошибки в формате RFC 9457. Схема в репозитории: `docs/openapi.json`.

## Если что-то пошло не так

- Прогон не стартует: `docker compose logs api`; без Docker `uv run green run ...` работает так же.
- Долгий прогон: показать готовый `out/demo/berzarina`, время по стадиям в `run_manifest.json`.
- CAD не показывает кириллицу в подписях: стиль `GREEN_TEXT` со шрифтом DejaVuSans; подписи дублируются в `interpretations.csv`.

## Что говорить про ограничения

Нормы: 75 из 76 правил с основанием по тексту акта, ссылки на СП 42.13330 по редакции 2016 года, как в ТЗ. Не определяются по чертежу: назначение здания (школа 10 м), демонтируемые объекты, охранные зоны сетей (заказчик сказал не применять). Приёмы размещения: аллея вдоль борта и сетка по газону; групповые композиции и CP-SAT не сделаны. Список полностью: `docs/architecture.md`, «Ограничения и следующие шаги».
