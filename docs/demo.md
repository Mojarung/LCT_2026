# Демонстрация проверяемого пайплайна: 8 минут

Состояние сценария: 23.09.2026, ветка `feat/verified-planting-pipeline`.
Показываем полный расчёт на аналитическом примере и диагностику реального входа.
Это разные доказательства: синтетический пример не измеряет точность распознавания
неизвестного DXF. Числа прогонов Берзарина от 18.09 остаются в исторических заметках;
они не являются результатом текущего строгого режима.

## Подготовка

Из корня репозитория:

```bash
uv sync
uv run python tools/record_experiment.py demo-prep -- uv run python tools/benchmark_universal_dxf.py --limit 1 --solver portfolio --work-dir out/demo-verified --output out/demo-verified/benchmark.json
uv run green serve --host 127.0.0.1 --port 8000
```

Драйвер создаёт `out/demo-verified/case-000/source.dxf`, точные назначения
`review.json` и готовый результат `reviewed/`. Это небольшая улица 120 × 60 м:
дорога снизу, газон между y=20 и y=55, здание сверху, водопровод по y=40.
Названия слоёв намеренно непрозрачны. Истину для демонстрации задаёт конструкция
генератора; назначения нельзя выдавать за результат распознавания или переносить
на чужой чертёж.

Открыть веб-интерфейс и подготовить локальный CAD для просмотра исходника и результата.
Целевая проверка в CAD под Linux обязательна по ТЗ. В текущей рабочей среде macOS
Docker отсутствует; новая ветка ещё не прошла такую проверку. Инструкция стенда —
[deploy.md](deploy.md). Старые контейнерные замеры не заменяют проверку этой ревизии.

## 0:00–1:00 — неизвестный вход

Загрузить `source.dxf`, выбрать `strict`, оставить дополнительные параметры пустыми.
Расчёт должен остановиться на неизвестных объектах. Открыть карту уточнения:
показать исходные формы, идентификатор, слой и причину неопределённости.

Фраза для показа: «Библиотека прочитала геометрию. По произвольному имени слоя
нельзя установить, водопровод это или другая линия. Неизвестное не стало грунтом
и не получило разрешение на посадку».

## 1:00–2:30 — уточнение и повторный запуск

По заданной схеме назначить на карте один объект и показать полученный JSON.
Для полного прогона взять подготовленный `review.json`: он содержит роли всех
объектов и подписи, а также хеш конкретного DXF. Загрузить тот же `source.dxf`
новым прогоном с профилем `strict`; вставить JSON в «Комплект файлов и параметры».

При показе через API эквивалентный запрос:

```bash
curl -s -F 'file=@out/demo-verified/case-000/source.dxf' -F 'profile=strict' -F 'overrides=<out/demo-verified/case-000/review.json' http://127.0.0.1:8000/api/v1/runs
```

Изменённый файл требует нового уточнения. Назначение роли объясняет объект,
но не подтверждает полноту топосъёмки или физические свойства грунта.

## 2:30–4:00 — пригодность и композиция

Показать дорогу, газон, здание, водопровод и получившиеся деревья/кустарники.
Объяснить: сначала проверяется вся площадь посадочного места, затем отступы;
виды проходят собственные ограничения и квоты. Пробуются несколько полных планов.

Открыть `portfolio.json`: baseline остаётся в сравнении, каждый вариант проходит
независимую проверку. Выбран наибольший итоговый индекс при заданных весах.
Открыть `quality.json`: показать слагаемые и их проектные допущения. Число мест
или статус MILP сами по себе не доказывают лучшую композицию. На этой сцене не
показывать «измеренный экологический эффект»: покрытие кронами — геометрический показатель.

## 4:00–5:30 — объяснение и три проверки

Выбрать дерево у сети: показать фактический отступ, расстояние до стенки трубы,
название правила и основание выбранного вида. Открыть ведомость посадочного материала.
Затем показать три независимых по назначению отчёта:

- `validation.json`: окончательные точки, виды, ямы, шаг, правила и квоты;
- `verify.json`: сохранность исходных сущностей, включая содержимое блоков;
- `export_validation.json`: записанные в DXF посадки соответствуют проверенному плану.

Зелёный статус относится к данным и правилам расчёта. Он не удостоверяет отсутствие
неизображённых сетей, пригодность реального грунта или полноту нормативной базы.

## 5:30–6:30 — результат и ручная правка

В CAD открыть `result.dxf`: исходник сохранён, посадки находятся на слоях `GREEN_*`,
вид и номер доступны в атрибутах. Использовать только реально проверенный CAD стенда.
В веб-интерфейсе включить правку и переместить дерево к водопроводу. Показать отказ
с причиной и повторную проверку при пересборке. При неуспешной пересборке ранее
проверенный DXF не заменяется ошибочным результатом.

## 6:30–8:00 — реальный вход и границы переноса

Встроенный участок Берзарина: «Проверить объекты». Показать неизвестные объекты
и подписи в контексте. Не обещать готовую строгую рассадку до уточнения.
Исследовательский эскиз включается отдельно и не является подтверждённым планом.

Показать [журнал экспериментов](research/verified-pipeline/findings.md): неизвестные
имена, вложенные блоки, единицы, поворот, отражение, штриховки с отверстиями,
отсутствующие XREF, ошибки чтения и независимые аналитические контрпримеры.
72 представления одной улицы — проверка переноса вычислений, а не 72 размеченные улицы.
Для неизвестного сложного DWG возможна остановка из-за потерь при конвертации;
REGION/ACADTABLE нельзя молча выкинуть ради результата.
## 6. Веб-интерфейс (2 мин)

`http://localhost:8000/` - то же, что делали командой, но глазами и без консоли.

1. Улица из списка пилотного проекта - первое, что видит человек на странице: девятнадцать
   улиц с готовыми комплектами подосновы и сетей, выбор в один клик. Для показа берём
   Камчатскую (39,5 МБ, полторы минуты): пока считается, внизу полоса хода с этапом,
   процентами и остатком, а чертёж появляется
   на карте, как только прочитан (около 40-й секунды), и его можно разглядывать - слои,
   масштаб, разворот вдоль улицы. По готовности посадки ложатся на тот же вид.
   Если датасет на стенде не смонтирован, на том же месте появляется встроенный фрагмент
   Берзарина (300 x 140 м, около двух тысяч посадок вместе с кустарником, около минуты) -
   показывать есть что в любом случае.
2. Карта плана на подоснове: сети по цветам, здания, граница работ, посадки кругом кроны.
   Вид развёрнут вдоль улицы, в углу стрелка севера и масштабная линейка; кнопка «по улице /
   по северу» возвращает ориентацию чертежа.
3. **Клик по дереву** - в панели вид, норма с наименьшим запасом и пункт акта с дословной
   цитатой. Это и есть требование интерпретируемости, предъявленное за десять секунд.
   То же самое доступно с клавиатуры: Tab на карту, стрелки - переход по посадкам вдоль
   улицы, Enter центрирует.
4. Клик по строке в составе плана подсвечивает этот вид на карте: видно, как разложены
   тринадцать видов и где сработали квоты разнообразия.
5. Включить «Правку плана», потянуть дерево к водопроводу: кружок краснеет **до** того, как
   отпустили кнопку. Отпустить - посадка уходит в отказы с названием нарушенной нормы.
   Без мыши то же самое: Alt со стрелками сдвигает выбранную посадку на полметра, а кнопка
   «Указать новое место на карте» в панели переносит её в точку следующего клика.
6. «Пересобрать DXF» - правка попадает в `result.dxf` и во все объяснения, целостность
   исходных слоёв проверяется заново.

Сказать вслух: интернета странице не нужно, внешних запросов она не делает.

## 7. API (1 мин)

`http://localhost:8000/docs`: `POST /api/v1/runs` с файлом и профилем, `GET /runs/{id}`, артефакты. Ошибки в формате RFC 9457. Схема в репозитории: `docs/openapi.json`.

## Если что-то пошло не так

- Прогон не стартует: `docker compose logs api`; без Docker `uv run green run ...` работает так же.
- Долгий прогон: показать готовый `out/demo/berzarina`, время по стадиям в `run_manifest.json`.
- CAD не показывает кириллицу в подписях: стиль `GREEN_TEXT` со шрифтом DejaVuSans; подписи дублируются в `interpretations.csv`.

## Что говорить про ограничения

Нормы: 75 из 76 правил с основанием по тексту акта, ссылки на СП 42.13330 по редакции 2016 года, как в ТЗ. Не определяются по чертежу: назначение здания (школа 10 м), демонтируемые объекты, охранные зоны сетей (заказчик сказал не применять). Приёмы размещения: аллея вдоль борта и сетка по газону; групповые композиции и CP-SAT не сделаны. Список полностью: `docs/architecture.md`, «Ограничения и следующие шаги».
