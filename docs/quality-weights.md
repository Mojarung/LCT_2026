# Веса индекса качества: как они получаются и как их проверить

Индекс качества плана v3 (`docs/notes/35-quality-index-v3.md`, прежний - `notes/29`) - взвешенная
сумма десяти слагаемых. Ни один акт весов не задаёт. Порядок получения весов с 26.09.2026:

1. **Нейтральный априор** - равные веса (OECD/JRC, Handbook on Constructing Composite
   Indicators, 2008, с. 31: без данных о предпочтениях - равные веса и анализ
   чувствительности).
2. **Подбор по принятым проектам** (`tools/quality_calibration.py`) - обратная оптимизация:
   принятый проект - выбор эксперта, наши варианты той же улицы - допустимые альтернативы;
   ищутся веса, при которых проект не хуже ни одного нашего варианта. Раздел «Подбор по
   принятым проектам» ниже.
3. **Анкета экспертов** (метод Саати, раздел «Анкета эксперта») - если заказчик даст панель:
   суждения экспертов важнее выведенных из проектов, потому что проект - выбор одного
   проектировщика, а не заказчика.

Источники, цитаты и статусы проверки - `docs/plans/2026-09-22-quality-literature.md`.

## Подбор по принятым проектам

Данные: состав новых посадок 17 принятых проектов по видам (`docs/data/designer-plans.yaml`,
наши подсчёты из описей улиц; сводка - `docs/notes/34-designer-practice.md`) и оценки
слагаемых всех проверенных вариантов нашего портфеля на тех же улицах (`portfolio.json` прогона
`tools/street_runs.py`, поле `terms` варианта). Цели участка у проекта те же, что у нашего
плана: длина улицы, вместимость, цели В.1.

У проекта без координат посадок считаются только слагаемые состава:

| Слагаемое | Как у проекта |
|---|---|
| Плотность | деревья и кустарники из ведомости к целям участка |
| Разнообразие | виды по ведомости, засчитывание долей, как в индексе |
| Категория | вид из ведомости сопоставлен каталогу по имени (вид, иначе род); вне каталога - половина балла |
| Сезонность | месяцы декоративности сопоставленных видов |
| Тень | только справка: сорта проектировщиков часто колоновидные («Crimson Sentry», «Fastigiata»), каталог даёт им крону исходного вида, и площадь крон завышена |

Пригодность месту, запас до сетей, ряды, ярусы и пылезащита требуют координат посадок
проекта; в сравнении они не участвуют, их веса остаются равными.

Задача - две линейные (HiGHS, `scipy.optimize.linprog`):

- коридор весов - от половины до двойного равного веса (0,05-0,2): ни один критерий не
  выпадает и не забирает индекс (OECD/JRC, с. 31-33 о доминировании одного измерения);
- шаг 1: минимум суммарного проигрыша проектов нашим вариантам, `Σ max(0, Q(вариант) -
  Q(проект))` по слагаемым состава;
- шаг 2: из весов с этим минимумом - ближайшие к равным (сумма модулей отклонений).

Смысл: веса меняются ровно настолько, насколько данные требуют, чтобы выбор проектировщика
был не хуже наших вариантов (обратная оптимизация: Ahuja, Orlin 2001; Chan, Lee, Terekhov
2019; порядковая регрессия UTA: Jacquet-Lagrèze, Siskos 1982). Если проект и без того не хуже
- равные веса данными не опровергнуты и остаются.

Устойчивость (OECD/JRC, шаг 7): бутстреп по улицам (400 розыгрышей) - разброс весов; веса
Дирихле вокруг найденных (2000 розыгрышей) - доля розыгрышей, где наш выбранный план не хуже
проекта по составу.

Запуск: `uv run python tools/quality_calibration.py --runs out/street-runs` после
`uv run python tools/street_runs.py --catalog dataset/streets_oda`; итог - в консоль и в
`out/quality-calibration.json`.

### Итог подбора

Прогон 27.09.2026: пакет улиц пилота в Docker, профиль `strict`,
`uv run python tools/quality_calibration.py --runs out/docker-batch`. В сравнение вошли
11 улиц с принятым проектом и надёжной описью, пар «проект - наш вариант» -
81; пропущены: Улица Нижние Поля, Измайловская площадь, Харьковский проезд, улица Берзарина, Улица Сергея Макеева (нет проекта, нет

| Слагаемое | Равные веса | Подобранные | Бутстреп, 5-95% |
|---|---|---|---|
| плотность | 0,1 | 0,05 | 0,05-0,05 |
| пригодность вида | 0,1 | 0,108 | 0,108-0,133 |
| разнообразие | 0,1 | 0,05 | 0,05-0,05 |
| ряды | 0,1 | 0,108 | 0,108-0,133 |
| ярусность | 0,1 | 0,108 | 0,108-0,133 |
| категория | 0,1 | 0,05 | 0,05-0,05 |
| тень | 0,1 | 0,108 | 0,108-0,133 |
| пылезащита | 0,1 | 0,108 | 0,108-0,133 |
| запас до сетей | 0,1 | 0,108 | 0,108-0,133 |
| сезонность | 0,1 | 0,2 | 0,05-0,2 |

Суммарный проигрыш проектов нашим вариантам: 1,755 при равных весах,
0,715 при подобранных.

Почему по умолчанию остаются равные веса:

1. Четыре веса из десяти упираются в границы коридора 0,05-0,2 (плотность, разнообразие,
   категория - в нижнюю, сезонность - в верхнюю), а сезонность в бутстрепе гуляет по всему
   коридору. Данные вес не определяют, они его выталкивают на границу.
2. Проекты выигрывают у наших вариантов в основном по тени: у них больше деревьев, потому что
   проект рубит существующие деревья и сажает на их месте (приложение B документации). Это
   разница в объёме работ, а не предпочтение проектировщика; подобранные веса закрепили бы её
   как предпочтение и занизили бы плотность, разнообразие и категорию, где наши планы сильнее.
3. Доля розыгрышей весов, где наш выбранный план не хуже проекта: Песчаный переулок 100%; 3-я Парковая улица 14%; улица Багрицкого 0%; Камчатская улица 0%; Лодочная улица 97%; Старый Гай ул. 87%; Наташинский пр-д (Дорога от ул. Борисовские пруды до пр.пр.5396, вокруг м-р Братеево) 0%; Куликовская улица 100%; Малая Грузинская ул. 0%; Кустанайская улица 0%; 2-я Прядильная ул. 18%. Разброс от 0 до 100% по улицам
   веса не объясняют: на Багрицкого и Малой Грузинской проект сажает деревья на месте
   вырубаемых, а у Наташинского проезда наш план в пакете занижен ошибкой распознавания
   (приложение B документации).

Подобранные веса остаются проверкой чувствительности: ими можно пересчитать выбор варианта
параметром `quality_weights` профиля.

## Что говорит методичка

- «Weights are essentially value judgements» (с. 31): веса - суждение, поэтому их берут у
  экспертов, а не выдумывают.
- Иерархия в два уровня (с. 31): при разных размерах групп равные веса слагаемых смещают веса
  групп. У нас четыре группы.
- Парные сравнения по шкале Саати 1-9, отношение согласованности CR < 0,1 (с. 97-98, со
  ссылкой на Saaty 1980).
- Проверка устойчивости Монте-Карло: все спорные решения разыгрываются разом, смотрят, как
  сдвигаются места (шаг 7, с. 117-121).
- Слагаемое, которое на плане не определено, выпадает, веса остальных нормируются (с. 120) -
  так индекс и устроен.

## Группы

| Группа | Слагаемые | Вопрос | Вес сейчас |
|---|---|---|---|
| Надёжность | пригодность вида месту, категория МГСН В.6, запас до сетей | выживет ли посадка и устоит ли план при проверке на месте | 0,35 |
| Функции | тень, пылезащита, ярусность | что посадки дают улице (заказчик, QA:39) | 0,30 |
| Состав | разнообразие, ряды, сезонность | устойчивость к вредителям и облик | 0,20 |
| Объём | плотность МГСН В.1 | не мало ли посадок | 0,15 |

Порядок «объём ниже прочего» задал заказчик: «лучший вариант не самый плотный, а
функциональный» (`docs/notes/15-organizers-qa.md`, вопрос 11).

## Анкета эксперта: 15 суждений, 5-10 минут

Число - во сколько раз первое важнее второго: 1 - равно, 3 - умеренно, 5 - заметно, 7 -
сильно, 9 - абсолютно; 2, 4, 6, 8 - промежуточные. Если важнее второе - обратная величина
(1/3).

Группы (6 сравнений): надёжность / функции; надёжность / состав; надёжность / объём;
функции / состав; функции / объём; состав / объём.

Внутри групп (по 3): пригодность / категория, пригодность / запас, категория / запас; тень /
пылезащита, тень / ярусность, пылезащита / ярусность; разнообразие / ряды, разнообразие /
сезонность, ряды / сезонность.

Кого спрашивать (OECD, с. 96): заказчик ДПиООС; ландшафтные архитекторы и дендрологи;
эксплуатация («Жилищник», ГБУ «Автомобильные дороги»); желательно эколог. Члены команды
экспертами не считаются. Разумная панель - 5-8 человек.

## Как посчитать

Анкеты складываются в YAML (формат и пример - `docs/quality-ahp-example.yaml`), затем:

```
uv run python tools/quality_weights.py анкеты.yaml
```

Скрипт печатает веса каждого эксперта с CR, отбрасывает несогласованные анкеты (их надо
вернуть эксперту), сводит остальные геометрическим средним суждений и выдаёт строки
`quality_weights` для профиля. Математика - `src/green/application/quality/weights.py`,
тесты - `tests/test_quality_weights.py`.

Нынешние веса по умолчанию - черновик команды, а не суждение экспертов; пример анкеты,
который их воспроизводит, - `черновик-команды` в `docs/quality-ahp-example.yaml` (CR 0,022).

## Как проверить устойчивость

```
uv run python tools/research/quality_robustness.py --api http://127.0.0.1:8000
```

Берёт последний прогон каждой улицы и разыгрывает 2000 вариантов: схему весов (нынешние,
равные, ROC по порядку заказчика), возмущение весов групп x U(0,5; 1,5) и выпадение одного
слагаемого. Печатает средний сдвиг места R_S (OECD, ур. 38) и для каждой улицы медиану и
разброс её места. Критерий приёмки из ресерча: медианный сдвиг не больше 2 позиций.

Первый прогон на 17 улицах (индекс прошлой версии, 22.09.2026): медиана R_S 1,88, 95-й
процентиль 4,0. Индексы улиц близки (0,43-0,55), поэтому отдельные улицы ходят широко, и это
честный результат: по нему видно, какие места в рейтинге улиц вообще можно утверждать.

## Цели слагаемых и их источники

| Цель | Значение | Источник |
|---|---|---|
| Тень | полный балл с 75% потенциальной площади крон | Kenney, van Wassenaer, Satel 2011, с. 110, 114: «optimal» 75-100% |
| Запас до сетей | 0,5 м сверх нормы | СП 317.1325800.2017, п. 5.3.5.3: сети на плане 1:500 - до 0,5 м от натуры |
| Пылезащита | метр борта под кустарником - полностью, только под кроной дерева - x0,5; полный балл с 50% | Abhijith et al. 2017, с. 83: в уличном каньоне работает низкий сомкнутый ярус, кроны над дорогой ухудшают воздух у земли; 0,5 и 50% - параметры проекта |
| Разнообразие | 10 эффективных видов, квоты 10-20-30 | Santamour 1990; Jost 2006 (exp(H) - число видов); Galle et al. 2021 (у уличных реестров exp(H) 17-37) |
| Плотность | 150-180 деревьев и 600-720 кустарников на 1 км | МГСН 1.02-02, табл. В.1 |
| Штрафы, сезонность, нижняя ветвь плотности | 0,05 и линейные шкалы | источника нет - параметры проекта |
