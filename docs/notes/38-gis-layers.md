# 38. Слои ГИС: GeoJSON и SHP на входе (27.09.2026)

ТЗ, п. 1: сервис принимает не только геоподоснову, но и данные публичных кадастров,
функциональное зонирование, элементы городской среды (data.mos.ru: улицы, здания, границы
участков) и охранные зоны; раздел «Ресурсы» называет SHP и GeoJSON. Такие слои подаются рядом
с чертежом: поле `layers` в API и форме, `green run ... --layer файл` в CLI.

## Что происходит со слоем

1. Чтение (`infrastructure/gis/layers.py`): GeoJSON (`.geojson`, `.json`) и SHP (`.zip` с
   `.shp`, `.shx`, `.dbf`, `.prj`; в CLI можно и `.shp` рядом с остальными файлами).
2. Система координат. Слой с явной системой (член `crs` GeoJSON, `.prj` SHP) с кодом EPSG или
   в долготе и широте (GeoJSON по RFC 7946, выгрузки data.mos.ru) пересчитывается в систему
   чертежа - местную МСК-Москва (`drawing_crs` в `config/geo_layers.yaml`, pyproj). Слой в
   метрах без системы координат принимается как есть. Проверка параметров: точка посадки
   Кустанайской (16 046,25; -5 738,63) переходит в 55,61520 с. ш., 37,75284 в. д. - сама улица.
3. Погрешность пересчёта (`transform_error_m`, 1 м) записывается в `geometry_error_m` объекта
   и входит в запас каждой проверки расстояния до него - так же, как погрешность геометрии
   чертежа. У местного слоя она 0.
4. Класс объекта - по первому совпавшему правилу `config/geo_layers.yaml`: атрибут
   `green_class` (любой класс сервиса), затем имя файла (охранные зоны ЛЭП и газопровода,
   здания, деревья, ограждения, граница работ). Кадастровые участки и функциональное
   зонирование принимаются к сведению: посадка и так ставится только внутри границы работ,
   вид территории по 369-ПП задаёт профиль. Объект без правила в расчёт не входит и
   перечисляется в предупреждениях.
5. Объекты встают в сцену после классификации чертежа (`PlanSite._with_gis_layers`):
   размещение, итоговая проверка плана и правка на карте видят их как объекты подосновы.
6. Совмещение (`application/gis_alignment.py`): каждое здание слоя сопоставляется с
   ближайшим зданием чертежа, медиана расстояний между центрами - в сведения прогона; больше
   3 м - предупреждение «проверьте систему координат слоя». Сервис сдвиг не исправляет.

## Охранные зоны из слоя

Классы `zone.power_line` и `zone.gas` - полигоны зон, внутренность занята. Правила
`R-OHLZONE-*` (ПП РФ N 160, п. 10 «в») и `R-GASAREA-*` (ПП РФ N 878, п. 16): посадочная яма
(дерево r = 1,24 м, куст 0,5 м) не заходит в зону без письменного согласования - вердикт
«требует согласования». Слой подаётся явно, поэтому эти правила действуют и при ответе
заказчика про охранные зоны сетей (вопрос 8: не строить зоны по линиям сетей поверх
отступов табл. 9.1).

## Проверка

`tests/test_gis_layers.py`: местный слой и класс по имени файла; WGS 84 -> МСК-Москва на точке
Кустанайской с погрешностью в запасе; `crs` EPSG:3857 и атрибут `green_class`, `ignore` и
объект без класса; SHP в архиве с `.prj`; оценка совмещения по зданиям; сквозной прогон
синтетической улицы с зоной газопровода: ни одна посадка, яма которой заходит в зону, не
проходит как «допускается», в плане есть `R-GASAREA-TREE-001`, в сведениях - запись о слое.

## Ограничения

- Параметры МСК-Москва общеизвестные (tmerc, эллипсоид Бесселя, towgs84), их точность на
  уровне дециметров не подтверждена; поэтому погрешность 1 м входит в запас проверок, а
  совмещение по зданиям показывает фактический сдвиг.
- Охранная зона задаётся только полигоном из слоя; по линии сети из чертежа зона газопровода
  строится правилом `R-GASZONE-*`, которое по ответу заказчика отключено в профилях.
