# 31. Веб-интерфейс на React вместо Jinja2

23-24.09.2026. Ветка `feat/react-frontend`. Спека и план - `docs/plans/2026-09-23-react-frontend-design.md`,
`docs/plans/2026-09-23-react-frontend-plan.md`.

Команда решила 23.09: веб-интерфейс - только SPA на React или Vue, серверные шаблоны не используем.
Взяли React: под бонус ТЗ (визуализация участка после финального DXF) у него готовые
`react-three-fiber` и `drei`, а для карты и форм разницы между фреймворками нет - карта
рисуется своим движком на canvas. Прежние Jinja2-страницы (`notes/25`) удалены целиком.

## Что сделано

- `frontend/`: React 19, TypeScript в строгом режиме, Vite 8, React Router (два маршрута),
  TanStack Query (данные сервера и опрос хода прогона), Zustand (рабочее место).
- Консоль `/`: улица пилота или свой комплект, профиль норм с параметрами из
  `GET /profiles/{name}` (форма отправляет только отличия от профиля), встроенный участок,
  если каталога улиц нет, реестр прогонов.
- Рабочее место `/runs/:id`: ход прогона поверх уже прочитанного чертежа и переход к плану без
  перезагрузки, сводка, панель посадки (вид, вердикт, норма с наименьшим запасом, акт, пункт,
  цитата, ценность для индекса), качество и состав плана, легенда со слоями, выгрузки с
  размерами, правка плана и пересборка DXF.
- Бэкенд под SPA: прогон улицы через `POST /api/v1/runs` (`street`), `POST /runs/demo`,
  `size_bytes` у артефактов, `GET /profiles/{name}`; раздача бандла `interfaces/web/spa.py`;
  Swagger из бандла; jinja2 удалён из зависимостей.
- Docker: стадия `node:24-slim` собирает бандл, в рабочем образе node нет (`docs/deploy.md`).

## Решения и почему так

**Карта - свой движок без React** (`src/map/`). Перенос прежнего `plan.js`: чанки `Path2D` по
классу, полке размера и ячейке сетки 24 x 24, растровый кэш с запасом 260 px, отсечение, ввод.
React владеет только панелями; движок получает данные через методы, а наружу сообщает через
хуки, которые страница держит в ref. Иначе каждая отрисовка React пересоздавала бы сцену на
десятки тысяч объектов.

**Стили перенесены, а не придуманы заново.** `app.css` разрезан по областям с теми же именами
классов, без CSS Modules: вид прошёл три итерации жюри, и переписывать его вместе со стеком -
значит заново проходить все три. Опечатку в имени CSS-переменной ловит тест
(`src/styles/tokens.test.ts`): палитра подставляет запасной серый, и ошибка иначе не видна.

**Крупный вид стоит на посадках.** Правка жюри (итерация 3): лента по короткой стороне на 55%
высоты, но не крупнее трёх видов «весь план». На фрагменте Берзарина центр габаритов пришёлся
на узел сетей, а посадки ушли под правую панель - центр теперь берётся по медиане посадок, и
окно не выходит за концы ленты (`src/map/view.ts`, тесты). Кнопка «вписать» стала «весь план».

**Пересборка «готова», когда прогон вернулся с новой отметкой времени**, а не когда пришёл
ответ 202: прежний интерфейс писал «пересобраны» до начала работы. Правки идут строго по
очереди, ответы живой проверки точки с устаревшим номером отбрасываются.

**Перенос без перетаскивания (WCAG 2.2, 2.5.7).** Alt со стрелками двигает выбранную посадку на
0,5 м (с Shift - на 2 м) с живой проверкой, на сервер уходит одна правка на серию нажатий;
кнопка «Указать новое место на карте» ждёт клик по карте. Выбранная посадка объявляется для
читалки экрана через область, смонтированную вместе со страницей. Уход со страницы при
непересобранном DXF спрашивает подтверждение.

**Числа через Intl, по русской норме**: запятая в дроби, разряды с пяти знаков через
неразрывный пробел (`18 780`, `13 567,52`), четырёхзначные слитно (`1964`) - разорванное
«1 964» в крупном моноширинном числе читалось как два числа.

**Раздача бандла** (`spa.py`): на маршруты клиента - `index.html`, отсутствующий файл - 404, а
не страница (битая ссылка на скрипт иначе ломает интерфейс молча), без сборки - 503 с
командой, API при этом работает. Файлы с хешем в имени кэшируются навсегда, `index.html` -
нет. Тип файла задан явно: на Windows `mimetypes` читает реестр, где `.js` бывает `text/plain`,
а модульный скрипт с таким типом браузер не исполняет.

## Ограничения

- На тяжёлой улице перерисовка начисто после остановки руки - один кадр в 83-148 мс: заметно,
  если водить карту рывками. Во время движения кадр не дольше 3 мс.
- Удаление посадки не отменяется: API не умеет восстанавливать.
- Движок карты не тестируется в jsdom (нет canvas): его проверяют модульные тесты вида и
  выбора, сквозной сценарий и живой браузер.
- Ручная проверка с читалкой экрана не проводилась - только автоматический скан и дерево
  доступности.
- Уход по ссылке «все прогоны» при непересобранном плане не спрашивает: правки остаются на
  сервере, пересобрать можно, вернувшись.
- Windows: фоновый `green serve`, снятый без дерева процессов, оставляет рабочие процессы
  Granian, и они держат `.venv\Scripts\green.exe` - `uv sync` падает. Сервер для проверки
  лучше поднимать в контейнере или через Playwright (он снимает дерево целиком).
