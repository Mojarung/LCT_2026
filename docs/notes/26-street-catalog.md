# 26. Каталог улиц пилотного проекта (22.09.2026)

Раньше прогон начинался одним из двух способов: встроенный фрагмент Берзарина или свой файл.
Улицы пилота при этом лежали в архиве и до сервиса не доезжали. Теперь список улиц есть в
форме и в API, и прогон по любой из них запускается в один клик.

## Что лежит на диске

`Пилотный проект 20 улиц.zip` - 11,4 ГБ, 1008 DWG, ни одного DXF. Распаковывать его целиком
незачем: из каждой улицы нужен только комплект подосновы. Этим занимается
`tools/prepare_streets.py`:

```powershell
uv run python tools/prepare_streets.py --list            # что будет выбрано, без конвертации
uv run python tools/prepare_streets.py --workers 4       # собрать каталог
uv run python tools/prepare_streets.py --only 16         # одну улицу
```

Результат - `dataset/streets_dxf/<slug>/*.dxf` и `catalog.json` рядом. 19 улиц, 2,5 ГБ,
конвертация в четыре процесса заняла около двадцати минут. Улицы 11 в архиве нет вовсе.

## Как выбирается подоснова

У двадцати улиц двадцать способов назвать геоподоснову: `ГЕО+Границы работ.dwg`, `гео.dwg`,
`10004588_улица Берзарина_ГП.dwg`, `Л_ИТП_Топография.dwg`, `ИП_Макеева С. ул.dwg`. Поэтому
отбор идёт по именам с оценкой, и его видно до запуска (`--list`):

- в плюс: `гео`, `топограф` (+6), `ГП`, `генплан`, `генеральный план` (+4), `АПОТ` (+1);
- в минус до полного отказа: дендроплан, посадочный план, озеленение, проектное решение,
  благоустройство, ОДД, ИОТ, портфолио, архив, «деревья к удалению» - это ответ
  проектировщика или чужой слой, а не вход;
- **файлы меньше мегабайта не могут быть подосновой**: `Собранная ГЕО.dwg` на 100 КБ - это
  обёртка с ссылками на внешние чертежи, геометрия лежит в них, а xref у нас не
  разворачивается. Имя у такой обёртки как раз самое подходящее, отсекает её только размер.

К подоснове добавляются выгрузки Мосгеотреста по видам сетей (`...tp`, `...up`, `...kl`,
`...pp`) - по одному файлу на вид, потому что в архиве каждая лежит в двух-трёх копиях. Без
них на плане нет половины ограничений. Сервис умеет комплект, и склейка работает: на
Кустанайской 13 500 + 5 149 сущностей дали 18 649 в объединённом чертеже.

## Как это устроено в сервисе

- `green.application.ports.StreetSource` и `StreetCatalog` - порт: улица это подоснова плюс
  комплект, каталог умеет `all()` и `get(slug)`.
- `green.infrastructure.streets.JsonStreetCatalog` - чтение `catalog.json` с перечитыванием
  по mtime. Улица без основного файла на диске пропускается: строка в списке, которая падает
  при выборе, хуже отсутствия строки. Битый JSON тоже даёт пустой список, а не отказ страницы.
- `GREEN_STREETS_DIR` - где лежит каталог, по умолчанию `dataset/streets_dxf`. В образе
  `/dataset/streets_dxf` (см. `compose.yaml`). **Каталога может не быть вовсе** - на стенде
  жюри датасет не монтируется, и это нормальное состояние: список улиц просто не
  показывается, остаётся встроенный фрагмент и загрузка своего файла.
- `POST /web/runs` принимает либо `street`, либо файл; выбранная улица имеет приоритет.
  Копирование комплекта идёт фоном вместе с прогоном: подоснова весит до двух сотен
  мегабайт, и копировать её в обработчике запроса значит держать event loop.
- `GET /api/v1/streets` - тот же список для клиента, в Swagger.

Прогон работает со своей копией, а не со ссылкой на файл каталога: план правят на карте, и
правка не должна доставать до общих данных.

## Что показал первый прогон по улице из датасета

Кустанайская улица (комплект из двух файлов, 34 МБ DXF): 1057 посадок, из них 1054 без
ограничений и 3 на согласование, 1510 мест отклонено, исходные слои целы, 136 секунд.
В предупреждениях - то, что и ожидалось от настоящего чертежа: 211 записей починил ремонт
строк, один блок в комплекте пришлось переименовать при склейке, 130 мест остались пустыми
из-за квот разнообразия.

## Чего не сделано

- Содержимое выбранной подосновы не проверяется: если у улицы в исходных данных оказался не
  тот файл, это видно только по прогону. Отбор по именам, а не по классификации сцены.
- Прогон запускался не по всем 19 улицам: проверены Кустанайская и Камчатская.
- Улицы 11 (Фрунзенская) в архиве нет; у Песчаного переулка нет папки исходных данных, взят
  генеральный план из «Генеральный план редформат».

## Грабля: по одному файлу на вид сетей - это половина улицы без сетей (22.09.2026)

Первая версия отбора брала «по одному файлу на вид» (`tp`, `up`, `kl`, `pp`), считая, что
остальные - копии. На Песчаном переулке это дало картину, в которой чертёж будто состоит из
двух кусков, идущих в разные стороны: на юге одни сети без топографии, на севере одна
топография без сетей.

Разбор показал, что перевёрнутых слоёв нет, координаты общие, а причина в отборе. Улицу
покрывает **несколько планшетов** Мосгеотреста, у каждого свой комплект выгрузок:
`output_1-3__3_ДЖКХ-25_02794{tp,up,kl,pp}` на северную половину и
`output_1-5__3_ДЖКХ-25_00752{tp,up,kl,pp}` на южную. Дедупликация по одному лишь виду
оставляла `tp` от первого планшета и `up` от второго - то есть топографию одной половины и
сети другой. В цифрах прогона: юг 4 882 объекта, из них 4 580 сетей и ни одного борта;
север 9 350 объектов, из них сетей 277.

Последствие было не косметическим. На половине без сетей алгоритму ничего не мешало, а
границы работ в комплекте нет вовсе, поэтому он засадил её сплошняком: 1 550 посадок,
из них полторы сотни каждого вида подряд.

Отбор теперь дедуплицирует по паре «планшет + вид» (`sheet_of()` убирает из имени признак
вида), потолок комплекта - 13 файлов. У половины улиц комплект вырос с 5 файлов до 13,
каталог - с 2,5 до 2,8 ГБ.

Заодно: генплан АПОТ Песчаного переулка - это оболочка из 29 внешних ссылок, вставленных в
нуле координат с единичным масштабом. Своей геометрии в нём 31 сущность, всё остальное -
в `Xrefs\*.dwg`, которые мы не разворачиваем. Поэтому проверка склейки «габариты
перекрываются» сравнивала комплект с пустым габаритом основы и честно писала 0% про каждый
файл. Теперь она сверяет файл с уже склеенным комплектом, а вырожденный габарит пропускает.

## Границы работ лежали в архиве отдельным файлом (22.09.2026)

Второе следствие того же разбора. У Песчаного переулка прогон писал «Граница работ не
найдена: размещение по всему чертежу», и алгоритм сажал деревья по всей подоснове, включая
чужие дворы: с неполным комплектом 1 550 посадок, с полным (сети на обе половины) - 5 546.

Граница в датасете есть, просто отбор её не брал: `output_1-3__brd.dwg`, `01_Границы
работ.dwg`, `brd_Грузинская М.ул.dwg`. Такой файл нашёлся у 16 улиц из 19; у остальных трёх
границы внутри основного файла («ГЕО+Границы работ»). Внутри - слой «Граница заказа», он уже
есть в `layer_map.yaml` как `work_boundary`, поэтому `ConstraintIndex` берёт его сразу:
кандидаты вне контура отсекаются проверкой `contains`.

Оговорка: «граница заказа» - это контур, на который заказывалась съёмка Мосгеотреста, а не
юридическая граница работ по проекту. Для нас это ограничитель участка, и он честнее, чем
отсутствие ограничителя вовсе, но на защите называть его надо своим именем.

Пустые файлы границ в архиве тоже есть (0 байт под тем же именем), поэтому отбор берёт
только непустые.

## Что показал прогон по всем улицам (22.09.2026)

Полный комплект (подоснова + сети всех планшетов + границы работ) прогнан через сервис по
каждой улице каталога, по одной за раз. Все прогоны прошли, целостность исходника цела
везде. Числа - в `docs/notes/28-all-streets.md`.

Главное, что вскрылось:

- **Нижние Поля ул** - единственная улица, у которой границ работ нет нигде: ни отдельным
  файлом в архиве, ни слоем в основном чертеже. На 218 МБ подосновы алгоритм поставил
  18 780 посадок, то есть засадил весь лист. Прогон об этом предупреждает, но предупреждение
  лежало в свёрнутом списке наравне с «аудит исправил 503 записи», поэтому такие
  предупреждения вынесены в сводку прогона рядом с числом посадок.
- **Внешние ссылки** - у восьми улиц генплан подтягивает часть содержимого через xref
  (у Куликовской их 47). Мы xref не разворачиваем: до алгоритма доезжает только то, что
  лежит в самом файле и в комплекте. На нормы это не влияет - считается по тому, что есть, -
  но полнота подосновы у таких улиц ниже, чем кажется по размеру файла.
- **Разные единицы чертежа** в комплекте (Песчаный, Старый Гай): файлы заявляют разные
  `$INSUNITS`, координаты при этом сходятся. Единицы определяются по геометрии
  (`docs/notes/22`), поэтому склейка верна, но заголовкам файлов верить нельзя.
