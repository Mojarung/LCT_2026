# Приём комплекта из нескольких DXF (18.09.2026)

## Шаг 1. Основание

Заказчик на сессии вопросов (`notes/15-organizers-qa.md`): на входе только DXF, файлов может быть несколько, генплан в одном, геоподоснова в другом (вопрос 3); сборный чертёж из внешних ссылок подаётся целиком (вопрос 4). Проектировщик вручную делает то же самое: накладывает чертежи по координатам и получает рабочий генплан (вопрос 12). До правки `green run` принимал один файл, генплан Олимпийской деревни склеивался вне сервиса.

## Шаг 2. Как устроено

- CLI: `uv run green run основа.dxf сети.dxf покрытия.dxf граница.dxf --profile strict`. Первый файл - основа, остальные догружаются в её модель. DWG в комплекте конвертируются по одному тем же конвертером.
- API: `POST /api/v1/runs` принимает поле `extra` (несколько файлов DXF или DWG) рядом с `file`.
- Порт `DrawingMerger` в `application/ports.py`, адаптер `infrastructure/cad/merge.py` на `ezdxf.xref.load_modelspace` (ezdxf 1.4.4, сигнатура сверена по докстрингу установленной версии).
- Объединённый чертёж сохраняется в каталоге прогона как `merged_source.dxf`. Дальше конвейер работает с ним как с обычным входом: результат пишется в его копию, целостность сверяется с ним же.
- Имена ресурсов. Одноимённые слои разных файлов остаются одним слоем (политика `KEEP`): по имени слоя работает классификатор. Если у файлов совпадают имена пользовательских блоков, включается `NUM_PREFIX`: совпавшие ресурсы догружаемого файла получают префикс `$0$`, иначе блок получил бы геометрию из другого файла. Префикс `$0$` классификатор слоёв и читатель блоков уже понимают (так выглядят внедрённые XREF).
- В предупреждения прогона попадают: число сущностей каждого файла и объединённого чертежа, расхождение суммы, разные `$INSUNITS`, смена политики имён.

## Шаг 3. Проверка

Тесты `tests/test_multi_dxf.py`: улица в одном DXF, водопровод с подписью диаметра в другом. План держит отступ от трубы из второго файла, в результате есть слои обоих файлов, целостность `ok`. Прогон с одним файлом склейку не запускает.

Реальный комплект: четыре выгрузки Геотреста по заказу 25_03117 (Олимпийская деревня) в DWG: топоплан `tp`, подземные сети `up`, план покрытий `pp`, граница `brd`. Раньше они склеивались вручную вне сервиса. Файлы скопированы в короткий путь: на Windows путь длиннее 260 символов ломает `dwg2dxf`.

```
GREEN_LIBREDWG_BINARY=<путь к dwg2dxf> uv run green run tp.dwg up.dwg pp.dwg brd.dwg --profile strict --set planting_category=yards --out out/check/olymp_kit
```

| Показатель | Значение |
|---|---|
| Сущностей в файлах | tp 217 417, up 87 286, pp 2 781, brd 1 485 |
| В объединённом чертеже | 308 969, сумма сошлась |
| Имена блоков | в трёх файлах по одному блоку с именем из основы, совпавшие ресурсы получили префикс `$0$` |
| Деревьев | 3 542, 14 видов, Шеннон 2,43, квоты выдержаны (при ручной склейке было 3 540) |
| Целостность | ok, 507 532 исходные сущности без изменений |
| Время | 323 с: конвертация 10, склейка 67, чтение 46, размещение 59, подбор 24, запись 49, проверка 62 |

Попутная находка: файлы `sample_*.dxf` из первых проб конвертации оказались разными листами (топоплан 320 x 260 м против остальных файлов на весь заказ). Сервис их склеил, сумма сущностей сошлась, но посадок не вышло: подписи покрытий и граница заказа лежат в разных местах. Несогласованный комплект по предупреждениям не распознаётся, проверка перекрытия габаритов файлов записана в план.
