# Скан всех DWG датасета (15.09.2026)

Для всех путей DWG «Пилотного проекта 20 улиц» предпринята конвертация через `dwg2dxf` (LibreDWG 0.14, Windows); каждый **успешно полученный** DXF просканирован потоково по тегам без загрузки в ezdxf: версия, единицы, типы сущностей, слои, блоки. Скрипты: `tools/dwg_scan.py`, `tools/dwg_summary.py`. Сырые результаты в scratchpad сессии (`dwgscan/results.jsonl`, 1009 строк).

## Конвертация

| Показатель | Значение |
|---|---|
| Путей с расширением .dwg | 1009 |
| Заглушки `PaxHeader` (артефакт распаковки tar, по 240 байт) | 190 |
| Настоящих DWG | 819 |
| Сконвертировано | 749 |
| Не сконвертировано | 70, все из одной выгрузки Геотреста «17.Наташинский_ГЕО_ЦВЕТ» (заказ 3ДЖКХ-25_00694), продублированной в пяти папках |

Причина 70 отказов: путь длиннее 260 символов (до 405), Windows-сборка `dwg2dxf` возвращает `READ ERROR 0x1000` (IOERROR). Один из отказавших файлов, скопированный на короткий путь, конвертируется (DXF 34 МБ). Это подтверждает причину для проверенного образца, но не является повторным успешным прогоном всех 70 файлов. На Linux такого ограничения Windows-пути не ожидается; результат в контейнере для каждого файла ещё нужно проверить. У успешно просканированных DWG версии от AC1015 (2000) до AC1032 (2018).

Кодовая страница везде ANSI_1251. `$INSUNITS`: 727 файлов в метрах (6), 13 в миллиметрах (4), 6 в дюймах (1), 3 в футах (2). Читатель пока считает всё метрами: нужна проверка `$INSUNITS` с предупреждением или пересчётом (в план).

Время конвертации: 1666 с суммарно на 749 файлов при 6 потоках, максимум 118 с (гео.dwg Нижних Полей, 330 тыс. сущностей). Самые большие DWG 66 МБ. Всего 10,8 млн сущностей.

## Что лежит во входных данных по улицам

Состав «Исходных данных» разный, три типа файлов:

1. Выгрузки Геотреста: tp (топоплан), up (сети), pp (проектируемые сети), kl (красные линии), brd (рамки). Имена разные: `output[1-18]_3_ДЖКХ-25_03117tp.dwg`, `tp_Грузинская М.ул.dwg`, `Л_ИТП_Топография.dwg` и `Л_ИТП_Коммуникации.dwg` (Лодочная), `XREF_ИГДИ_*.dwg` (Камчатская, 2-я Прядильная), `00.1_10004141_Топография.dwg` и `00.2_..._Сети.dwg` (Кустанайская), `гео.dwg` (Нижние Поля). Имена слоёв внутри одинаковые, кроме 3-й Парковой: там префиксы `Топо_` и `Сущ_Сети_` (`Топо_Бортовой камень`, `Сущ_Сети_Кабель защиты`). Есть у 17 улиц из 20.
2. Дендрологические изыскания проектировщиков (`ИП_*.dwg`, «Дендрология.dwg», «ДИ+граница.dwg»): слои `!!!_1. Дендра_сохранить` (блоки существующих деревьев, 42,8 тыс. вставок в 17 улицах), `Дендра_вырубка`, `Дендра_номера_*`, `Дендра_выноски_*`, `Дендра_Аварийка_*`. Это второй источник существующих деревьев, точнее условных знаков топоплана.
3. Генпланы проектировщиков (АПОТ, слои `ДВ_ГП_*`, `_АД_*`, `Борт ...`, `!Project_road kerb`): проектные борта, штриховки покрытий смежных территорий (`ДВ_ГП_СМЕЖ_ПЧ`, `_ТРОТ`, `_ГАЗОН`), газоны, `ДВ_ГП_П_Граница работ`, МАФ, опоры освещения. У Измайловской площади и Берзарина в исходных данных только такие файлы и дендроплан, выгрузки Геотреста нет.

Слои легенды Геотреста `Условные_штампы` и `Условники_штампы`: 1,6 млн отрезков в 15 файлах двух улиц, это штампы условных знаков вне плана. Отправлены в ignore, иначе они и время чтения, и «сеть неизвестного типа» через fail-closed.

## Классификатор после правок

Доля сущностей входных данных без класса: 29% до правок (2,0 млн), 0,5% после (33 тыс.). Остаток: текстовые слои проектировщиков, точки разбивки, пандусы, воздуховоды, конкретные типы покрытий `ДВ_ПП_ДО_Тип*` (в них есть тротуары и проезжая часть по типам ремонта, стоит разнести по классам позже).

По классам во входных данных (сущностей): ignore 3,88 млн, силовые кабели 803 тыс., существующие деревья 714 тыс., борт 225 тыс., газон 216 тыс., водопровод 161 тыс., водосток 161 тыс., связь 123 тыс., здания 109 тыс., газ 105 тыс., канализация 104 тыс., опоры 101 тыс., теплосеть 84 тыс., колодцы 62 тыс., дренаж 46 тыс., ЛЭП 26 тыс., сети неизвестного типа 22 тыс., сооружения 11 тыс., тротуар 5,4 тыс., граница работ 2,5 тыс., трамвай 2,1 тыс., проезжая часть 1,4 тыс.

Полигоны проезжей части и тротуаров есть только в АСУ ОДХ и в генпланах проектировщиков (штриховки `СМЕЖ_*`, `ДВ_ПП_ДО_Тип*`). В выгрузках Геотреста их нет, отсюда проблема стороны борта (см. план).

## Эталонные проектные решения

Слои посадок у каждого проектировщика свои, единой схемы нет:

- блоки посадочных мест: `(ГП)Посадочное место`, `_ГП_Оз_Посадки проектируемые`, `ГП_посадочный`, `!Посадки`, `! ПР ДЕРЕВЬЯ`, `ГП_зеленые насаждения`, `СП_дендроплан`, `04 Дендроплан (растения)`;
- по видам в имени слоя: `PLNT_TREE_Яблоня Недзвецкого`, `DENDRO_BUSH_Лапчатка кустарниковая 'Маунт Эверест'`, `PL_BUSH_Спирея Японская`, `06_ДП_ПузыреплодЛЮТЕУС_план`, `(ГП)Гортензия метельчатая`;
- привязки и размеры: `(ГП) Привязка дер и куст`, `#04_размеры посадочный`, `Размеры посадка`, `Новый_РЧ ОЗ_границы групповых посадок`;
- Куликовская и Понтрягина: все слои с суффиксом `_Ном._пера__N` (экспорт по перьям), топоплан продублирован как `Новый_! Съемка_...`.

Для сравнения с эталоном (план, пункт 7) нужен словарь слоёв посадок по улицам и извлечение точек из блоков; сами файлы с посадками есть у 17 улиц (у 2-й Прядильной папки проектного решения нет, у Лодочной один лист без посадок).
