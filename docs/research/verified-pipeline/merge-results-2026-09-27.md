# Объединение с main: что оставлено и чем проверено

Проверено 27.09.2026. Удалённый `main` обновлён через `git fetch` до
`07e4f7e`. Исходная экспериментальная ветка — `17feaa0`, сохранена также
в `backup/verified-pipeline-before-main-20260927`.

## Решение

В `feat/verified-planting-pipeline` объединён актуальный main. Основа рабочего
кода, конфигурации, UI, зависимостей и тестов взята из main; экспериментальные
варианты заменены его реализациями. Поверх оставлены три небольшие доработки
и исправлен обнаруженный при сравнении дефект нового этапа газонов.

| Изменение | Польза и границы |
|---|---|
| Ограниченная область неопределённости повреждённого HATCH | Сохраняет исходную заливку для CAD и отображения, но запрещает посадку в отдельно ограниченной области. Не отнимает большую площадь вокруг локального разрыва. Неподдерживаемая граница остаётся ошибкой чтения. |
| Чтение пустых записей ACAD_TABLE от конвертера | Пропускаются только записи без владельца, proxy-графики и содержательных DXF-тегов. Таблица со ссылкой на блок или содержимым по-прежнему блокирует небезопасный ремонт. Удаление пустых записей явно отражается в диагностике. |
| `assume_unknown_geometry=false` | Сохраняет словарь и вывод по именам, отключает замену неизвестной геометрии на предположительно безопасный контур. Работают существующие уточнения слоёв и объектов. Режим включается явно. |
| Исключение сомнительного материала из газонов | Новый этап main брал исходный полигон грунта без маски неопределённости. Теперь газон вырезает её, как уже делают проверки деревьев и кустарников. |

Старый подбор видов с дополнительным ремонтом рядов, альтернативный reader,
ACIS-конвертер и прежний web review не входят в итоговый рабочий код.
Их выигрыш относительно развитого main не подтверждён; прежний исходник и
исследовательские материалы доступны на сохранённом коммите. Новые словари
имён конкретных улиц ради результатов этого сравнения не добавлялись.

## Сравнение на одинаковых входах

В таблице указаны деревья / кустарники. Для всех вариантов задан `spacing_m=6`;
остальные параметры взяты из профиля соответствующей версии. Поэтому сравнение
со старой веткой отражает весь продукт, включая различия профилей. Main и
объединённая версия используют одинаковую конфигурацию.

| Вход | Старая ветка | Main 07e4f7e | Объединённая версия |
|---|---:|---:|---:|
| Размеченный контрольный участок | 62 / 18 | 68 / 95 | **68 / 95** |
| Тот же участок с разрывом HATCH | 53 / 63 | 34 / 77 | **66 / 95** |
| Дополнительный распознанный водопровод | — | 65 / 89 | **65 / 89** |
| Реальный фрагмент Берзарина | В этот повтор не включён | 64 / 1271 | **64 / 1271** |
| Реальная Измайловская: чтение | — | Ошибка ACAD_TABLE | **7282 объекта**, затем блокировка из-за 4 отсутствующих XREF |
| Собранный Харьковский, DXF 147 МБ: только чтение | — | 279362 объекта | **279362 объекта**, геометрический барьер пройден |

На исправном участке, распознанном водопроводе и Берзарина совпали не только
количества, но и **все координаты с назначенными видами**. Для HATCH доступная
площадь выросла с **759 до 1961 м²**; сомнительная область не разрешена под
деревья. После дополнительного исправления площадь газона внутри повреждённого
прямоугольника снизилась со **120 до 0 м²**.

Во всех завершённых расчётах успешны `verify`, `validation`,
`export_validation`. Для Берзарина **1335 из 1335** посадок имеют хотя бы одну
строку объяснения с актом и пунктом. Это проверка структуры объяснений и
встроенных ограничений, а не независимая экспертиза исходного чертежа.

### Неизвестные объекты

Контрольный пример: дополнительная диагональная линия с нейтральным именем слоя.
По условию эксперимента это водопровод; алгоритм этого имени не знает.

- Main и обычный режим объединённой версии размещают **3 дерева ближе 2 м**
  к этой линии. Существующая геометрическая догадка main остаётся риском.
- С `assume_unknown_geometry=false` расчёт останавливается для уточнения.
- После явного назначения слоя классу `utility.water` получены **65 деревьев
  и 89 кустарников**, 0 деревьев внутри 2 м; координаты и виды совпадают с
  вариантом, где слой изначально правильно назван.
- На большом Харьковском в этом режиме остаются **906 неопознанных объектов**.
  Такой файл ещё требует разбора. Нулевое число неизвестных в обычном режиме
  не является измерением точности распознавания.

Включение через CLI:

```bash
uv run green run input.dxf --profile strict --set assume_unknown_geometry=false
# После проверки, что этот слой действительно содержит водопровод:
uv run green run input.dxf --profile strict --set assume_unknown_geometry=false \
  --set 'layer_classes={"Layer-73":"utility.water"}'
```

В интерфейсе используется JSON дополнительных параметров
`{"assume_unknown_geometry": false}`. Уточнения также доступны через существующий
экран разбора. Этот режим не проверяет истинность совпадений по словарю и не
заменяет экспертизу грунта, сетей или полноты комплекта.

## Проверки

Main и объединённая ветка получили отдельные окружения через `uv sync --frozen`
из одного актуального `uv.lock`; прежнее ограничение с отсутствующими
зависимостями main устранено.

| Проверка | Результат |
|---|---|
| Старая ветка: импорт, HATCH, ассортимент, синтетический pipeline | 59 passed |
| Полный backend main | **1822 passed, 5 skipped** |
| Полный backend объединения до последней правки газонов | **1834 passed, 4 skipped** |
| После исправления газонов: расчёт, газоны, эффекты, редактирование, CAD, семантика | **120 passed** |
| После эквивалентного упрощения маски газонов для линтера | **30 passed** |
| Дополнительные тесты HATCH | Метры/миллиметры, вложенная вставка, поворот, разные масштабы осей и XCLIP прошли |
| Frontend | **253 passed**, production-сборка прошла |
| Статические проверки | Ruff на всём `src` и затронутых тестах, ty, оба архитектурных контракта прошли |

Регрессионный тест газонов сначала воспроизвёл ошибку: 9 м² сомнительной площади
попадали в газон. После исправления он проходит; сквозной повтор HATCH подтвердил
нулевое пересечение и успешный DXF-экспорт.

Полный `ruff check src tests` на чистом main и объединении показал одинаковые
**10 уже существовавших замечаний в других тестах**. В изменённых исходниках и
тестах новых замечаний нет. Docker, Linux CAD и браузерный e2e в этом запуске
не проверялись. Некоторые backend-тесты пропускаются без дополнительных локальных
данных/артефактов; число пропусков также зависит от наличия собранного frontend.

## Доказательства и воспроизведение

- [Компактные результаты 22 запусков](merge-results-2026-09-27.json): SHA-256
  каждого входа, параметры, статусы, количества, хеш координат/видов и проверки.
- Полные локальные артефакты: `out/merge-comparison-2026-09-27/`.
  `merged_hatch` — промежуточный результат до исправления газонов;
  `final_hatch` — сквозная проверка исправления.
- [Общий исполнитель сравнения](../../../tools/research/cross_branch_eval.py)
  запускается отдельным процессом с `PYTHONPATH=<checkout>/src`, принимает
  `--root`, `--source`, `--out`, `--variant`, `--overrides` и `--stage read|plan`.
  Ошибка сохраняется в `result.json`: код завершения инструмента сам по себе
  не означает успешный расчёт.
- Контрольные геометрические сценарии воспроизводятся в
  `tests/test_hatch_uncertainty_integration.py`, `tests/test_hatch_footprint.py`,
  `tests/test_documents_audit.py`, `tests/test_unknown_geometry_policy.py`,
  `tests/test_lawns.py`.
- Предыдущее сравнение и причины отказа от полного переноса экспериментального
  кода: [26.09](main-comparison-2026-09-26.md),
  [оценка относительно ТЗ](merge-tz-assessment-2026-09-26.md).

Замеры времени выполнялись одновременно с тестами и не доказывают ускорение.
На Харьковском проверено чтение, не полный расчёт посадок. Для реальных улиц
нет независимой полной разметки грунта и сетей: увеличение числа посадок само
по себе не доказывает повышение качества проекта.

Следующий полезный шаг: проверить собранную ветку на полном комплекте выбранной
улицы, подтвердить классы неоднозначных объектов и открыть результат в целевой
CAD-среде. Текущие результаты обосновывают выборочное объединение; универсальную
корректность любого DXF они не устанавливают.
