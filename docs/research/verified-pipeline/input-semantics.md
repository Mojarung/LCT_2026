# Как работать с незнакомыми слоями

DXF хранит геометрию и имя слоя, а не гарантированный тип реального объекта.
Наша таблица правил — набор предположений по именам. `confirmed` в старом YAML
значит «наблюдали в пилоте», а не «эксперт подтвердил объект этого файла».
Это не вероятность и не процент точности.

Обычный запуск останавливается до размещения, если пространственный объект остался
неизвестным, одинаково приоритетные правила дали разные классы либо известен только
класс `utility.unknown`. Отказ не удаляет предыдущий результат. CLI и API сохраняют
`classification.json`, в том числе у неуспешного прогона. На его странице есть ссылка.

В отчёте записаны хеш DXF и таблицы правил, все правила, группы по слою, блоку,
геометрии, выбранному классу и основанию решения. Счётчики полные, примеров ссылок
не более пяти на группу. `ready` означает отсутствие неразрешённых назначений
в импортированной геометрии; это не доказательство правильности имён и полноты съёмки.
Потеря геометрии и недостающие XREF проверяются раньше, отдельным барьером.

## Осмотр и уточнение

```sh
green inspect drawing.dxf > review.json
green run drawing.dxf --out out/reviewed \
  --set 'layer_classes={"drawing$0$L17": "utility.water", "L26": "lawn"}'
```

Через API или поле дополнительных параметров веб-формы передаётся тот же JSON:

```json
{
  "layer_classes": {"drawing$0$L17": "utility.water", "L26": "lawn"},
  "block_classes": {"WELL_SYMBOL": "utility.access"},
  "feature_classes": {"12345678:00000000:AB": "pole"}
}
```

Примеры имён условные: нужно использовать **полные имена из конкретного отчёта**.
Неизвестный ключ останавливает прогон, чтобы опечатка не выглядела применённым
исправлением. Имена сопоставляются без учёта регистра и с нормализацией Unicode;
регулярных выражений в этих трёх параметрах нет. `feature_classes` приоритетнее
`block_classes`, а тот приоритетнее `layer_classes`. Уточнение одного объекта нужно
для смешанного слоя; назначать весь такой слой газоном нельзя без проверки.
Составная ссылка объекта включает хеш файла и меняется при изменении DXF — старое
уточнение не должно молча применяться к другому исходнику.

Автоматические правила работают с именем **без пространства имён XREF**: файл
`Газон.dwg` не превращает все свои внутренние слои в газон. Правило блока-символа
конкретнее правила слоя. Внутри одной цели используется явно заданный `priority`;
перестановка равноприоритетных правил не разрешает противоречие. Приоритет 10 у
старой грамматики плана покрытий отделяет новый материал от материала после
«за счёт». Все совпадения сохраняются, включая проигравшие правила.

Положительный класс `lawn` дополнительно проверяется на контекст работ. Имена
«ТРОТ за ГАЗОН», «устройство газона», «газон новый», «газон под демонтаж» и
аналогичные известные формулировки не устанавливают готовый грунт: результат
`unknown`, причина `material_context`. Нужны выбранная стадия проекта и явное
назначение для этого входа. `layer_classes`/`feature_classes` разрешают такое
уточнение и сохраняют исходные совпадения в отчёте. Это консервативный фильтр
известных опасных формулировок, не полный анализ естественного языка; молчаливо
принимать новую формулировку за достоверный грунт всё ещё нельзя.

Имена `0`, `Layer1`, `Грунты`, `0_геоподоснова` сами по себе не разрешают исключить
геометрию. Фонтаны, крыльца и другие пространственные объекты тоже больше не
скрываются общим правилом оформления. Содержимое `DIMTXT` сначала читается полностью,
а уже затем правило класса `ignore` помечает его как оформление; это решение видно
в отчёте и его можно переопределить.

## Исследовательский режим

`require_known_objects=false` позволяет исследовать поведение старого алгоритма
при неполной семантике. Это **не подтверждённый план**. В сводке будет
`semantic_assignments_complete=false`, сохранятся отчёт и предупреждения.
`unknown_lines_as_utility` остаётся только эвристикой: проектные 2 м вокруг неизвестной
линии не доказывают безопасность для любого типа объекта. Неизвестные точки и площади
тем более не получают такой гарантии.

Кнопка проверки встроенного реального фрагмента остаётся строгой. Отдельная кнопка
«Посмотреть эскиз» явно включает исследовательский режим: в этом фрагменте есть
неуточнённые слои, и интерфейс сообщает, что допустимость не подтверждена.
Обычная загрузка файлов этот режим не включает.

Отдельное предположение о покрытиях: `surface_inference_mode=distance` разрешает
распространение меток по расстоянию для эскиза и выставляет
`surface_inference_review_required=true`. По умолчанию подписи используются только
в замкнутых гранях покрытия; см. [surface-topology.md](surface-topology.md).

## Граница решения

Совпавшее, но ошибочное имя слоя всё ещё может дать неверный класс. Проверки правил
не заменяют сведения о фактическом грунте, актуальности сетей и скрытых объектах.
Чтобы оценить точность распознавания, нужен независимый размеченный набор новых
чертежей. До него нельзя считать долю назначенных классов точностью и автоматически
повышать доверие по числу успешно пройденных синтетических тестов.

Из них следует устройство формата; выбор строгого отказа — политика этого проекта.
