## Что исправлено относительно main

- Локальная неопределённость повреждённого HATCH исключена из посадок и газонов,
  исходный объект сохраняется в DXF. Контуры с противоречивыми подписями больше
  не разрешаются повторно через распространение материала по близости.
- Перестановка сущностей и перенос координат больше не меняют подбор видов
  на двух контрольных реальных планах: было 6/6 и 24/20 изменений видов,
  стало 0/0 в обоих экспериментах. Точность геометрии не уменьшена.
- Сводка проверяет всю посадочную яму, различает грунт по замкнутым контурам
  и по эвристике. Интерфейс явно показывает эскиз и число непроверенных ям.
- `review` отключает догадки о неизвестных объектах. Обычный профиль сохранён
  для совместимости; для неизвестного входа рекомендован `review`.
- Устранены 10 замечаний Ruff в существующих тестах.
- Сборка LibreDWG ограничена одним процессом по умолчанию: запуск на все ядра
  исчерпал память проверочной VM с 4 ГБ. Число процессов настраивается через
  `LIBREDWG_BUILD_JOBS`.

Это улучшение безопасности, повторяемости и диагностики. Процент улучшения
«правильности рассадки» по этим данным посчитать нельзя: нет полной экспертной
разметки новых реальных участков.

## Независимые геометрические зоны

До первого расчёта зафиксированы 16 DXF и геометрия правильного ответа, seed
`20260928`. Четыре семейства: газон с отверстием, отдельные островки, вогнутый
контур, косые границы; случайные размеры, повороты и переносы. Код приложения
после просмотра этих результатов не подстраивался.

Проверка использует исходные полигоны и прямые расстояния Shapely, без классификатора,
маски грунта и валидатора приложения. Проверены вся круглая яма в грунте и границе,
дерево–водопровод 2 м, дерево–борт 2 м, дерево–существующее дерево 5 м,
куст–существующее дерево 1 м, пары новых деревьев 5 м, допуск 0,002 м.
Во всех случаях прошли также сохранность подосновы, валидация плана и совпадение экспорта.

Это независимость проверочной геометрии от реализации алгоритма, **не внешняя
экспертиза и не 16 реальных улиц**. Набор покрывает указанное подмножество правил.
Качество грунта в натуре, все инженерные нормы и красоту композиции он не подтверждает.

Воспроизведение:

```sh
.venv/bin/python tools/research/independent_zones.py --out out/new-independent-zones
```

Инструмент сначала сохраняет весь набор, затем считает планы. При повторе проверяет
SHA-256 сохранённых DXF и возвращает ненулевой код при нарушении проверяемых условий.

До запуска выбраны четыре файловых варианта двух заказов:

не засчитан успешным. Списки исходников, SHA-256 и ошибки сохранены в JSON;

а не успешную рассадку. Для расчёта нужен полный DXF или корректное преобразование CAD.

## Linux-проверка

Образ `40bdd03ca434` собран из проверенного кода: Python 3.14.7, LibreDWG 0.14.
В VM 4 ГБ RAM, выполнение x86-64 через QEMU на ARM64. Первое падение компилятора
подтверждено записью OOM ядра; последовательная сборка прошла.

CLI на `zone-01` без сети (`--network none`) дал 78 посадок, как на Mac,
встроенные проверки прошли. Внутренний HTTP API на `zone-00` дал 83 посадки
(31 дерево, 52 куста), 0 нарушений независимого оракула. На Mac на этом входе
получено 103 посадки (40/63): варианты MILP в эмуляции остались на жадной базе.
Повтор с `placement_time_limit_s=30` дал **103 посадки (40/63)**, индекс около
0,8122 против 0,812812 на Mac; 0 нарушений оракула, целостность и экспорт прошли.
Количество восстановилось, идентичность координат и видов этим не утверждается.
Это подтверждает влияние вычислительного бюджета. Нельзя утверждать одинаковое
качество на любом железе при фиксированном времени поиска.

Обычный запуск Granian под этим QEMU падал при импорте. Тот же образ запускается
с `QEMU_GUEST_BASE=0x800000000000`; код и зависимости не изменялись. Описание
и источник гипотезы — в [развёртывании](../../deploy.md#проверка-x86-64-через-qemu-на-apple-silicon).
Проброс порта Podman на хост не заработал; проверка HTTP сделана внутри контейнера.
OCI-формат Podman отбросил HEALTHCHECK; его точная команда выполнена вручную успешно.
Эти ограничения среды не скрываются под формулировкой «целевая машина проверена».

## Граница готовности

Исправления можно оценивать как улучшение помощника для предварительного проектирования:
на проверенных входах нет регрессии сохранности DXF или нарушений выбранных геометрических
ограничений. Безопасный маршрут для нового файла — `review`, уточнение неизвестных
объектов, проверка грунта, затем просмотр результата проектировщиком в CAD.

Не доказаны: экспертная правильность всех грунтов, пригодность ямы в натуре, полная
инвариантность к повороту, поддержка любого DWG и работа именно в МосТех.ОС/CAD заказчика.
Отдельный Linux-контейнер под эмуляцией не заменяет последний пункт и не даёт корректного
замера скорости на целевой машине. Формулировка «алгоритм полностью готов для любого
входа без проверки человека» результатами не поддерживается.

Локальные полные артефакты: `out/holdout-release-2026-09-27/`,
`out/release-verification-2026-09-27/`, журналы `out/experiments/`.
В `experiments.jsonl` записи этой итерации имеют префикс `e-release-`.
