# E82: локальная визуальная модель для семантики CAD (25.09.2026)

Цель: проверить, помогает ли модель сопоставлять имена слоёв DXF с видимой
легендой проекта. Это диагностический опыт, **не оценка точности на независимой
размеченной выборке**. В продуктовый классификатор назначения не добавлены.

## Условия

- Хост: MacBook Pro M3 Pro, 36 ГБ RAM. `llama.cpp` 0.5.0, CPU only
  (`-ngl 0 --no-mmproj-offload`), 8 потоков, контекст 4096.
  Это не замер на целевом Linux с 16 ГБ RAM.
- Официальные GGUF Qwen3-VL-Instruct, Q4_K_M + Q8_0 projector:
  2B SHA256 весов `089d75c52f4b7ffc56ba998ffc50aae89fcafc755f9e7208aacca281dca6c2ae`,
  projector `f9a68fabba69c3b81e153367b2c7521030b0fa8bb0de400c9599c8e6725f9c82`;
  4B SHA256 весов `66358cb18bb6b3b1b6675aa412c7a88ef01d228f481184d13668e5201c730a0a`,
  projector `30ba2c7dd3127a4561b6cba9d13d0f711c91bdb38742e2f56d73c8cb596bd06d`.
  Температура 0. Обе модели отвечали через локальный HTTP сервер.
- Первый проект: план благоустройства Академика Понтрягина, DXF SHA256
  `75ea5d3f66d1845662b50f4db3c77934c631d03ed569399b18bd04a775ff132c`.

  Пять слоёв выбраны вручную: садовая лента, проектный газон, щепа, борт,

  Взяты шесть реально встречающихся слоёв с переходами материалов вроде

Наблюдаемая RSS процесса во время работы: около 3,47 ГБ для 2B и 5,42 ГБ
для 4B. Это отдельные снимки `ps`, **не пик потребления**, и к ним добавляются
память парсера, конвертера и других процессов. Совместимость со стендом 16 ГБ
и скорость под Linux не проверены.

### Вывод

На первом проекте 4B даёт полезные **предложения классов**, если предъявить
маленький фрагмент легенды. Но поле `confidence=high` и текст `evidence_quote`
не являются доказательством: модель уже сослалась на отсутствующие подписи.
Точная OCR-подпись сама по себе также не доказывает, что она относится к
конкретному DXF-объекту. На втором проекте запрос не уменьшил неопределённость.

Разумный следующий прототип: использовать модель для извлечения подписей и
предложения соответствий, затем проверять цитаты по видимому источнику,
сохранять `unknown` для неоднозначных переходов и запрашивать подтверждение
человека перед признанием пригодного грунта или снятием ограничений. До
независимой разметки по целым новым проектам нет оснований заявлять прирост
точности или заменять текущий строгий барьер модельным ответом.

Исходные PDF/DXF остаются в локальном датасете и `out/`; изображения вырезок,
веса и полные ответы модели лежат в `out/runtime/semantic-model/`. Эти файлы
не включаются в Git.
