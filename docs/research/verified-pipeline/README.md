# Проверяемый пайплайн посадок

Начало: 23.09.2026. Ветка: `feat/verified-planting-pipeline`.
База: `464467cc022b2e5fd157446981963155ed33d452` (`feat/web-ui`).
Пользователь разрешил исследования, локальные тесты, эксперименты, отдельную ветку,
коммиты и push. Чужая рабочая копия и её незакоммиченные изменения не используются.

## Цель и границы доказательства

Найти пригодные территории, построить хороший план деревьев и кустарников и проверить
результат отдельно от генератора. Отсутствие геометрии не доказывает отсутствие препятствия.
Процент распознанных имён слоёв не является точностью геометрии или семантики.
`verify.json` проверяет сохранность исходника, а не допустимость посадки.
Оптимум можно доказать только для явно заданных кандидатов, ограничений и цели;
он не доказывает лучшую архитектурную композицию среди всех непрерывных решений.

## Обязательное уточнение пользователя: неизвестные DXF

23.09.2026 пользователь отдельно подтвердил: заранее неизвестно, какие DXF будут
поданы; решение должно быть универсальным. Пилотные улицы — контрольные примеры,
а не перечень поддерживаемых входов. Нельзя улучшать метрику только добавлением
имён слоёв конкретных улиц или использовать проектные посадки как исходную истину.

Критерии переноса: геометрия сохраняется при переименовании слоя/блока; координаты
и отступы согласуются при переносе, повороте и смене единиц; незнакомая семантика
явно остаётся неизвестной; отсутствующие сети/поверхности/границы не становятся
разрешением. Нужны машинный отчёт прочитанного/пропущенного и явные сопоставления
слоёв/блоков с классами. Никакая геометрическая или нейронная эвристика не может
достоверно различить одинаково нарисованные безымянные кабель, водопровод и ограду
без дополнительной информации. Правильный исход такого случая — запрос данных
или сопоставления и ограниченный результат, а не выдуманный класс.

## Порядок работы

1. Воспроизводимый baseline, полный разбор ТЗ, инвентарь данных и разрывов входа.
2. Проверки полноты входа: XREF, неизвестные/потерянные сущности, единицы, границы.
3. Пригодность поверхности: неизвестное не становится грунтом; полигоны,
   ограниченное распространение подписей, неоднозначность, площадь посадочного места.
4. Независимый валидатор финальных координат и выбранных видов, шага, границ,
   отступов, условий и квот. Отдельные статусы корректности и полноты данных.
5. Сравнение генераторов и отбора: исправленный greedy, фазы/повороты сетки,
   совместный выбор кандидатов, MILP с оценкой разрыва до оптимума.
6. Повторяемые сравнения на синтетических краевых случаях и реальных улицах;
   эталонные посадки проектировщиков используются только для независимого сравнения.
7. Документация, ограничения, полный прогон проверок, коммиты и push.

## Источники и проверенные положения

- ТЗ ДПиООС, локальный PDF из комплекта, физические стр. 2–4: алгоритмический
  подход разрешён; нейросеть необязательна; обязательны DXF, неизменность подосновы,
  объяснение каждой посадки с нормой, деревья и кустарники.
- `docs/notes/15-organizers-qa.md`, 18.09.2026: вторичный конспект автоматической
  расшифровки. Не является подписанным изменением ТЗ. Исходные CAD нельзя передавать
  внешним сервисам; все эксперименты с ними выполняются локально.
- [ezdxf XREF](https://ezdxf.readthedocs.io/en/stable/xref.html), проверено 23.09:
  вставки имеют свои преобразования; `embed` загружает содержимое в определение блока.
  Поддержка DXF библиотекой не равна поддержке всех сущностей нашим reader.
- [SciPy milp](https://docs.scipy.org/doc/scipy/reference/generated/scipy.optimize.milp.html),
  проверено 23.09: есть статус завершения, dual bound и MIP gap. Таймаут с допустимым
  решением не даёт права называть решение оптимальным.

## Эксперименты

Каждый запуск тестов/бенчмарка выполняется через `tools/record_experiment.py`.
Машиночитаемый журнал: `experiments.jsonl`; полные локальные логи: `out/experiments/`.
Журнал хранит команду, версии, ревизию, fingerprint изменений, время и exit code.
Интерпретация результатов добавляется в `findings.md`. Сырые CAD и геометрия
заказчика в Git не добавляются.

Практический порядок уточнения незнакомых слоёв и границы исследовательского режима:
[input-semantics.md](input-semantics.md). Последняя проверка назначений на реальных
файлах: `semantic_survey.json`; это статистика неопределённости, не оценка точности.

Границы ошибки приближения кривых и их учёт в отступах и площадях:
[geometry-uncertainty.md](geometry-uncertainty.md). Локальная проверка четырёх DXF:
`curve_survey.json`; неподтверждённая геометрия останавливает расчёт.
