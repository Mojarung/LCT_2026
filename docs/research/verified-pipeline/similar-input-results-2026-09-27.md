# Проверка похожих входов — 27.09.2026

**Последующая проверка:** [измерение по отдельной визуальной разметке](soil-audit-2026-09-27.md)
дало 87 поддержанных разметкой ям из 88 и одну спорную при запасе 0,25 м.
Ниже сохранены выводы до этой проверки; экспертного подтверждения всё ещё нет.

## Вывод

На выбранных похожих входах существующие правила назначили классы всем
прочитанным объектам без расширения словаря. Два собранных реальных комплекта
дали 40 и 48 кустарников, с объяснениями и успешными внутренними проверками.
Однако все 88 мест зависят от эвристического определения грунта. Это главный
неустранённый риск качества в этой выборке. Правильность классификации и грунта
по независимой экспертной разметке пока не измерена.

На восьми новых контролируемых планах получено 170 деревьев и 376 кустарников;
отдельная проверка по исходной геометрии не нашла нарушений выбранных ограничений.
Это подтверждает часть геометрической корректности на новых компоновках,
но не доказывает качество на всех будущих файлах жюри.

## Основание и метод

- [Ответ организаторов](organizer-input-scope-2026-09-27.md) передан пользователем;
  оригинал переписки не проверен. Ожидаются аналогичные объекты и обозначения.
- Алгоритм зафиксирован на `7f4ece9`, ветка `feat/verified-planting-pipeline`.
  Код приложения и словари в ходе эксперимента не менялись.
- В локальном каталоге уже есть прежние проверки всех 19 основных пилотных улиц.
  Поэтому использованы другие конкретные исходные листы и сочетания листов,
  для которых в просмотренных отчётах не найден прежний сквозной прогон.
  Это не гарантия, что никто из команды их раньше не обрабатывал.
- Файлы отобраны до просмотра результатов, по структуре и близким обозначениям.
  Списки и SHA-256: [отдельные листы](similar-input-selection-2026-09-27.json),
  [комплекты](similar-package-selection-2026-09-27.json).
- Локальные исходники — DWG, преобразованы LibreDWG. Ошибки этого преобразования
  отделены от качества алгоритма на полноценном DXF, который ожидается от жюри.
- Полные машинные показатели без исходной CAD-геометрии:
  [результаты JSON](similar-input-results-2026-09-27.json).

### Что измерено по качеству двух полученных планов

| Показатель | Багрицкого, лист 1 | Наташинский, лист 8 |
|---|---:|---:|
| Посадки с объяснениями | 40 / 40 | 48 / 48 |
| Сохранность подосновы / валидация / совпадение экспорта | Все прошли | Все прошли |
| Центры посадок на грунте явных замкнутых контуров | 0 | 0 |
| Центры посадок на эвристическом грунте | 40 | 48 |
| Эвристический грунт карты, м² | 511,5 | 233,75 |
| Результат с `assume_unknown_geometry=false` | 0 деревьев / 40 кустов | 0 / 48 |
| Результат только с грунтом замкнутых граней (`closed_faces`) | 0 / 0 | 0 / 0 |
| Встроенный индекс качества, шкала 0–1 | 0,5215 | 0,5700 |

Индекс — собственная целевая функция, не экспертная оценка и не вероятность
правильности. Внутренний валидатор использует ту же распознанную сцену, поэтому
ошибочная поверхность может пройти и генератор, и проверку.

По визуализации посадки распределены группами внутри выбранной границы и
эвристической маски грунта. Подоснова насыщена сетями; отказ от новых деревьев
согласуется с записанными отказами по отступам. Это не доказывает, что допустимых
мест для деревьев в непрерывном пространстве вообще нет: алгоритм проверяет
свой набор кандидатов. Внешней оценки композиции и натурной проверки грунта нет.

Отдельная проблема представления уверенности: при такой зависимости от грунта
в отчёте `surface_inference_review_required=false`, а все 88 посадок имеют
статус `allowed`. Предупреждение об эвристике есть текстом. Пользователь может
переоценить надёжность результата; стоит явно связать статус посадки с источником
сведений о поверхности.

## 3. Новая геометрия с известным правильным ответом для ограничений

Созданы восемь синтетических DXF с близкими обозначениями. Геометрия грунта,
границы, водопровода, бордюра и существующего дерева задана и сохранена отдельно
до запуска алгоритма. Это новые тестовые планы, **не независимый реальный датасет**.

| Сценарий | Деревья | Кустарники | Нарушения проверенных ограничений |
|---|---:|---:|---:|
| Полоса грунта 2,2 м | 0 | 40 | 0 |
| Полоса 3,6 м | 10 | 22 | 0 |
| Полоса 12 м | 29 | 51 | 0 |
| Полоса 24 м с поперечным проходом | 41 | 55 | 0 |
| Два участка грунта с проходом, ширина 12 м | 21 | 53 | 0 |
| Полоса 12 м, миллиметры | 29 | 51 | 0 |
| Полоса 12 м, поворот 37° и вложенный блок | 20 | 52 | 0 |
| То же в миллиметрах | 20 | 52 | 0 |

Проверка напрямую по исходным полигонам и расстояниям Shapely, без вызова
классификатора и валидатора приложения:

- вся круглая посадочная яма внутри грунта и границы: радиус 1,24 м для дерева,
  0,5 м для куста;
- дерево не ближе 2 м к заданным водопроводу и бордюру, 5 м к существующему дереву;
- куст не ближе 1 м к существующему дереву;
- между новыми деревьями не менее 5 м; допуск вычисления 0,002 м.

Это выбранное подмножество настроенных ограничений, не независимая проверка
всех нормативов, ассортимента и инженерной пригодности. Все восемь прогонов
также прошли встроенные проверки подосновы, плана и экспорта.

Поворот и вложенность здесь изменены одновременно, их эффекты не разделены.
План не инвариантен к этому преобразованию: 29 → 20 деревьев. При этом собственный
индекс вырос с 0,904688 до 0,930746, оценочная площадь крон — с 463,3 до 498,4 м²,
а портфель имел допустимый вариант с 28 деревьями. Поэтому снижение количества
само по себе не доказывает ухудшение: изменились выбранные виды и композиция.
Для отдельной оценки устойчивости нужны независимые факторы и внешний критерий.

Воспроизведение в окружении проекта:

```sh
PYTHONPATH=src .venv/bin/python tools/research/similar_layouts.py --out out/similar-layouts-repeat
```

## Следующая итерация

1. Разметить вручную грунт на этих двух реальных листах до изменения эвристики:
   оценить долю посадочных ям, целиком попавших в подтверждённый грунт, и площадь
   ошибочно разрешённого покрытия. Это даст независимую метрику для улучшения.
2. Отдельно показывать посадки, зависящие от эвристического грунта, и подтверждать
   поверхность перед выдачей уверенного результата.
3. Доработать сборку смешанных версий DXF и проверку комплектности входа.
   Повторить на полном DXF без потери REGION; не обходить барьер полноты.
4. Сохранить эти входы как контрольные. Следующее улучшение оценивать также на
   других листах; не добавлять правила по названиям именно этих улиц.

Эти результаты не дают основания срочно заменять алгоритм нейросетью. Они
локализуют конкретную проблему: проверяемость грунта и полнота исходного плана.

Локальные полные артефакты: `out/similar-inputs-2026-09-27/`, визуализация
`real-plans.png`, независимый аудит поверхности `quality-audit.json`.
В Git включаются отчёт, агрегаты, списки источников и генератор синтетики;
исходные и производные реальные CAD-файлы остаются локальными.
