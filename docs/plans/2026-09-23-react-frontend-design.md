# Фронтенд на React: спецификация (23.09.2026)

Команда решила переписать веб-интерфейс: вместо страниц Jinja2 и ванильного `plan.js` -
одностраничное приложение на React. Решение закреплено правилом в `CLAUDE.md`: интерфейсы
только на React или Vue, серверные шаблоны не используем.

## Почему React, а не Vue

Сравнение по недельным скачиваниям npm на 23.09.2026, в тех местах, где у проекта есть
реальная потребность:

| Потребность | React | Vue |
|---|---|---|
| Фреймворк | react 133 млн | vue 12 млн |
| 3D на three.js (бонус ТЗ: визуализация участка) | @react-three/fiber 4,0 млн, drei 3,0 млн | @tresjs/core 28 тыс. |
| WebGL-слои в декартовых координатах чертежа | @deck.gl/react 0,4 млн | официальной обёртки нет |
| Данные с сервера | @tanstack/react-query 48 млн | @tanstack/vue-query 0,5 млн |

Скорость фреймворка на работу не влияет: тяжёлая часть - карта - рисуется canvas-движком мимо
фреймворка. Решает запас готового для 3D-вида участка, который идёт следующей задачей.

## Границы

Входит:

1. Одностраничное приложение в `frontend/` с тем же набором возможностей, что сейчас (список
   ниже), и в том же визуальном языке («графит и кость», IBM Plex, светлая и тёмная темы).
2. Доработки API, без которых интерфейс не может жить только на JSON: прогон по улице, демо,
   размер артефактов.
3. Удаление Jinja2: `interfaces/web/pages.py`, `templates/`, `static/`, зависимость `jinja2`.
4. Исправления, найденные аудитом и жюри дизайна, которые живут на стороне клиента:
   - «Вписать» подгоняет вид под план, а не под всю границу работ (главный минус вердикта
     жюри: чертёж занимал около 11% кадра);
   - правки уходят на сервер строго по очереди, ни одна не теряется;
   - статус пересборки честный: интерфейс ждёт её конца, а не пишет «готово» сразу;
   - Swagger UI работает без интернета (своя статика вместо CDN).
5. Docker: бандл собирается в отдельной стадии на node, в рабочем образе node нет.
6. Документация и карта проекта.

Не входит (отдельные задачи):

- 3D-вид участка на react-three-fiber (заявка на бонус ТЗ) - следующая задача после переноса.
- Серверные дефекты правки (кустарник проверяется нормами дерева, нет проверки шага между
  посадками, нет блокировки контекста) и прочие находки аудита по алгоритму.

## Что умеет интерфейс сейчас и должен уметь после переноса

Консоль (`/`):

- шапка: знак, версия, факты сервиса (правил всего и сверено, видов), переключатель темы,
  ссылка на Swagger;
- выбор улицы пилота из каталога (номер, название, число файлов, размер);
- загрузка своего комплекта: основной DXF/DWG, дополнительные чертежи, перечётка .xls/.xlsx;
- профиль, шаг посадки, галочки приёмов (барьеры, группы кустарника, ряд у борта, изгородь,
  подлесок, добор зоны), «продвинутый» JSON поверх профиля;
- кнопка демо (встроенный фрагмент Берзарина);
- последние прогоны со статусом.

Рабочее место прогона (`/runs/:id`):

- ход прогона: этап, доля, остаток, шаги; подоснова на карте сразу после чтения чертежа;
- предупреждения, меняющие смысл плана, - в сводке; остальные - в свёрнутом списке;
- карта: подоснова по классам, сетка в круглых метрах, масштабная линейка, север,
  посадки (деревья, кустарник, на согласование, с барьером), отказы, слабые места, места под
  барьер, слой покрытий «как понял сервис», подписи материала, выделение, подсветка вида;
- управление картой: колесо, перетаскивание, клавиатура, ползунок масштаба, «вписать»,
  ориентация по главной оси улицы, ссылка на место `#x=..&y=..&m=..`;
- панель обозначений со слоями и фильтр по видам;
- панель посадки или отказа: правило, акт, пункт, разобранная цитата (таблица или список),
  замер против нормы, основания вида, альтернативы, ценность посадки, барьер;
- индекс качества: итог, слагаемые с основаниями и весами, сильные и слабые посадки;
- правка: перенос с живой проверкой точки, удаление, пересборка DXF;
- файлы результата (главные отдельно, служебные свёрнуты) с размерами;
- ошибка прогона и пустые состояния.

## Архитектура

```
браузер: React SPA ──fetch──> FastAPI /api/v1 (JSON, RFC 9457)
                         └──> /api/v1/runs/{id}/artifacts/{name} (plan.json, basemap.geojson, ...)
FastAPI: /api/v1/* - API; /docs - Swagger с локальной статикой; всё остальное - SPA из GREEN_WEB_DIR
Docker: stage web (node) -> npm ci && npm run build -> /app/web в рабочем образе
```

### Изменения API

- `POST /api/v1/runs` (multipart): поле `file` становится необязательным, добавляется `street`
  (slug улицы из `/streets`). Нужно ровно одно из двух, иначе 422. С `street` поле `extra`
  запрещено (у улицы свой комплект), `inventory` принимается и уходит в прогон.
- `POST /api/v1/runs/demo`: прогон встроенного фрагмента с профилем по умолчанию, ответ 202
  и `Location`, как у обычного прогона.
- `ArtifactOut.size_bytes: int | None` - размер файла для списка «Файлы результата».
- `/redoc` убирается (грузит скрипт с CDN, ТЗ требует только Swagger). `/docs` берёт
  swagger-ui из `GREEN_WEB_DIR/vendor/swagger/`, если он собран; иначе - по умолчанию FastAPI.
- Веб-маршруты `/web/runs`, `/web/demo`, `/runs/{id}` (HTML) и `/static` удаляются.
- `docs/openapi.json` пересобирается, тест держит его в синхроне с кодом.

### Раздача SPA

`interfaces/web/spa.py`: для любого GET вне `/api`, `/docs` отдаёт файл из `GREEN_WEB_DIR`, если
он есть, иначе `index.html` (маршруты клиента). Запрос к несуществующему файлу из
`/assets/` - 404, а не `index.html`: иначе битая ссылка на скрипт превращается в HTML и
ломает страницу молча. Если бандл не собран, `/` отвечает 503 с одной строкой, как его собрать;
API при этом работает. `Settings.web_dir` (`GREEN_WEB_DIR`), по умолчанию `frontend/dist`.

### Приложение `frontend/`

- React 19, TypeScript в строгом режиме, Vite, React Router (два маршрута), TanStack Query
  (данные сервера и опрос хода прогона), Zustand (состояние рабочего места: выделение, слои,
  фильтр видов, режим правки, очередь правок).
- `src/api/`: типизированный клиент поверх `fetch`, разбор ошибок RFC 9457; типы API
  генерируются из `docs/openapi.json` (`openapi-typescript`), типы артефактов (`plan.json`,
  `basemap.geojson`, `rules.json`, `quality.json`, `surface.json`) описаны вручную по
  `infrastructure/reports/artifacts.py`.
- `src/map/`: движок карты на TypeScript без зависимости от React - перенос `plan.js`
  (чанки Path2D по классу и ячейке, растровый кэш подосновы, отсечение, попадание в
  объект, ввод). React-компонент `PlanMap` создаёт движок и передаёт ему данные и
  состояние. Производительность не хуже нынешней: кадр при перетаскивании не дольше 16 мс
  на Кустанайской.
- `src/lib/`: чистая логика с тестами - склонения, форматы чисел, разбор цитат норм,
  сборка параметров прогона из формы (перенос `_form_overrides`), ссылка на место,
  отбор предупреждений, геометрия вида.
- `src/pages/`, `src/components/`: страницы и панели; стили - CSS Modules на токенах из
  нынешнего `app.css`; шрифты IBM Plex лежат локально.
- Ни одного внешнего запроса: шрифты, иконки, swagger-ui - в бандле.

## Проверки: что значит «готово»

1. Python: `ruff check`, `ruff format --check`, `ty check`, `lint-imports`, `pytest` - зелёные.
2. Фронт: `tsc --noEmit`, ESLint (typescript-eslint, react-hooks, jsx-a11y), Prettier, Vitest -
   зелёные.
3. Playwright e2e на живом бэкенде (свой порт, личность сервиса проверяется по `/api/v1/meta`):
   консоль -> демо -> карта отрисована -> клик по посадке -> в панели правило, акт, пункт ->
   перенос посадки -> пересборка -> скачивание `result.dxf`; каждый запрос браузера идёт
   только на локальный адрес.
4. Скриншоты 1440, 1100 и 390 в светлой и тёмной теме, просмотрены глазами; всплывающие
   сообщения вызваны отдельно.
5. accesslint по живой странице и web-design-guidelines по коду - найденное исправлено.
6. Агент design-jury: PASS (не меньше 85, категории 1, 2, 3, 12 - не меньше 8).
7. Docker: образ собирается, контейнер healthy, `/` отдаёт интерфейс, демо проходит через
   интерфейс в контейнере, `/docs` открывается без интернета.

## Риски

- Верность переноса карты: `plan.js` - 2143 строки с тонкой оптимизацией. Переносится модуль
  за модулем с сохранением алгоритмов, замер кадра до и после.
- StrictMode в разработке монтирует эффекты дважды: движок карты обязан корректно
  создаваться и уничтожаться (снятие обработчиков, остановка анимаций).
- Большие артефакты (`plan.json` 20-40 МБ) грузятся целиком, как и сейчас; облегчение
  артефактов - отдельная задача.
