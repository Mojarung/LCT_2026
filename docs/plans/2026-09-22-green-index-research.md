# Оценка качества озеленения: что уже есть в проекте (22.09.2026, черновик)

Задача: не «нормы соблюдены», а **насколько план хорош**, плюс объяснение по каждой посадке -
чем именно она ценна. Этот файл - опорная точка ресерча: сюда собрано то, что уже посчитано
в коде и найдено в документах, чтобы следующая сессия не начинала с нуля.

## 1. Что сервис уже считает и складывает в артефакты

Проверено на живом прогоне (Камчатская, `var/runs/01a0c950.../output/`).

`plan.json` → `summary.stats`:

| Ключ | Что значит |
|---|---|
| `alley_candidates`, `alley_plantable` | сколько мест предложил приём «аллея вдоль борта» и сколько из них пригодны |
| `lawn_candidates`, `lawn_plantable` | то же для приёма «заполнение газона» |
| `surface_cells_soil`, `_paved`, `_barrier`, `_unknown` | карта покрытий: ячейки 0,5 м по типам |
| `zone_allowed_m2` | площадь зоны допустимости, м² |

`assortment.json` (по плану целиком):

| Ключ | Что значит |
|---|---|
| `counts` | сколько посадок каждого вида |
| `genus_shares`, `family_shares` | доли по родам и семействам |
| `conifer_share` | доля хвойных |
| `shannon` | индекс Шеннона по видам |
| `decor_by_month` | покрытие декоративности по месяцам |
| `no_species` | мест, отклонённых из-за квот разнообразия |
| `quota_violations` | нарушения квот на итоговом плане (обычно пусто) |
| `rejected_by_kind`, `rejected_by_rule` | отсев пар «место - вид» по основаниям |

У каждой посадки в `plan.json`: `assortment.percent` (оценка пригодности вида месту),
`assortment.factors` (разбивка процента по факторам), `structure`, `reasons` (с `rule_id` и
цитатой), `alternatives` (три лучших с процентами), `checks` (все проверенные нормы с
измеренным и пороговым расстоянием).

## 2. Что считается из этого в две строки кода

На той же Камчатской (51 посадка, 13 видов):

| Величина | Значение | Как получено |
|---|---|---|
| Площадь крон | 407 м² | сумма π·(d/2)² по `species.crown_diameter_m` |
| Доля зоны допустимости под кронами | 13% | крона / `zone_allowed_m2` (3 177 м²) |
| Эффективное число видов | 12,2 из 13 | exp(индекс Шеннона), Шеннон 2,50 |
| Доля самого частого вида | 10% | по `counts` |

То есть числитель и знаменатель для покрытия, разнообразия и плотности уже лежат в
артефактах: отдельный тяжёлый расчёт для сводной оценки не нужен.

## 3. Найденные основания для критериев

- `docs/spec.md:184` - метрики качества были заложены изначально: ноль нарушений жёстких
  норм, доля пригодной площади под посадками, индекс разнообразия, сравнение с эталоном по
  числу посадок и площади крон.
- `docs/algorithm.md:126` - разнообразие **намеренно** не входит в оценку подбора вида:
  «этого вида уже много» не должно смешиваться с «вид плохо подходит месту». Значит
  разнообразию место в сводной оценке плана, а не в оценке места.
- `docs/algorithm.md:106-108` - аллергенность и плодовый опад: запрет по п. 3.6.18 743-ПП,
  слабая аллергенность только снижает оценку. Готовый штраф для формулы.
- `ТЗ/research.md:247-256` - протокол оценки из пяти экспериментов: LOSO по улицам с F1
  попадания в полигоны проектировщика (допуск 0,5 м), компенсационный баланс по 743-ПП,
  слепой экспертный тест по критериям «корректность отступов» и «эстетика аллеи»,
  стресс-тест охранных зон, тест устойчивости парсинга.
- `docs/notes/06-surface-map.md:55` - сравнение с проектировщиком: 652 из 1 106 его деревьев
  попадают в 6 м от наших, 418 в 3 м. Дальше сравнивать предложено по плотности и видам, а
  не по точкам.
- `docs/notes/24-audit.md` - `green audit` меряет чужой план теми же правилами: у
  проектировщика Берзарина 391 посадка с нарушениями из 554, у нас 0 из 860. Готовая база
  для сравнения «мы против человека».
- `docs/notes/18-planting-schedule.md:19-25` - 515-ПП (стандарт и ком) и 743-ПП табл. 3.3.1
  (площадь посадочной ямы): 4,84 / 3,61 / 0,79 м² на посадку. Готовая стоимостная величина.

## 4. Инструмент для калибровки

`tools/research/replay_assortment.py` пересчитывает подбор по готовому `plan.json` без
чтения DXF - секунды вместо трёх минут. Тем же приёмом можно считать и сводную оценку по
всем 19 прогонам каталога, не запуская их заново.

## 5. Что дальше (замысел, не сделано)

Составная оценка плана из слагаемых, каждое из которых уже измеримо: соответствие нормам,
покрытие пригодной площади кронами, структура посадок (деревья / кустарники / газон),
разнообразие с целевым коридором, пригодность вида месту, сезонность, функции (затенение,
защита от дороги), штрафы (аллергены, инвазивные, пустые места из-за квот).

Ключевая идея для объяснения «чем важно это дерево»: **предельный вклад** - насколько
упадёт сводная оценка, если убрать именно эту посадку. Вклад считается точно, а не
оценивается на глаз; в сумме вклады индекс не дают (см. п. 20).

Открытые вопросы: откуда взять целевые значения (доля крон, доли типов посадок, коридор
разнообразия) - из актов, из эталонных планов проектировщиков или обосновать самим.

## 9. Чего в документах нет и придётся обосновывать самим

1. Целевого процента озеленения или покрытия кронами - нет нигде. Единственная плотностная
   норма - МГСН В.1, и её текста в папке актов заказчика нет (помечена `external`).
2. Весов составной оценки - ни один документ не говорит, что важнее: тень, разнообразие или
   число посадок.
3. **Правило 10-20-30 - не норма, а Santamour 1990** (`docs/plans/2026-09-16-assortment.md:34`).
   Индекс Шеннона - тоже наш выбор. Для кустарников источника нет вовсе
   (`docs/notes/16-categories-shrubs-barriers.md:54`). На защите называть своим решением.
4. Эстетики, сезонной декоративности и композиции нет ни в ТЗ, ни в актах, ни в ответах
   заказчика. «Эстетика аллеи» встречается только в нашем же `ТЗ/research.md:253`.
5. Шумо- и пылезащита названы заказчиком как функции хорошего плана, но ни один акт не
   говорит, **когда** шумозащитный ряд обязателен; МГСН задаёт только геометрию ряда.
6. Списка аллергенных и токсичных видов акт не даёт - отнесение вида наше, с источником.
7. «Элементы скверов» (ТЗ:85) названы типом и нигде не раскрыты.

## 10. Осторожно с внешним ресерчем

`ТЗ/research.md` - наш внешний отчёт, а не документ заказчика, и он местами противоречит и

# Что уже считает код (разбор src/green, 22.09.2026)

## 11. Сырьё для оценки уже есть почти всё

На каждую посадку (`domain/planting.py:194-205`) лежит:

- `checks` - **все** проверенные правила, а не только нарушенные, у каждого `measured_m`,
  `threshold_m`, `nearest` (ссылка на сущность DXF), `object_class`. Запас по норме
  (`measured_m - threshold_m`) уже вычисляется в `explain.py:113`, но нигде не сохраняется.
- `notes` - приём размещения: «аллея вдоль борта», «заполнение газона», «группа кустарников»,
  «посадка с прикорневым барьером» (`placement.py:44-48, 374-377`).
- `assortment` (`planting.py:147-157`): `percent` 0-100, `factors` (7 факторов в [0,1]),
  `structure_kind` (row / group / single), `reasons` с `rule_id` и цитатой, три `alternatives`.

Оценка вида - нормированная взвешенная сумма (`assortment/scoring.py:47-66`):

| Фактор | Что считает | Вес |
|---|---|---|
| `site` | уплотнение и аллергенность; у дороги ближе 5 м добавляются соле- и газоустойчивость | 0,30 |
| `function` | есть ли у вида применение под структуру (ряд / группа / солитёр), под ВЛ | 0,20 |
| `decor` | месяцы декоративности из 12, плюс 0,25 вечнозелёным | 0,15 |
| `longevity` | долговечность к 150 годам | 0,15 |
| `care` | уровень ухода 1-3 | 0,10 |
| `pilot` | сколько улиц пилота уже содержат вид, к 7 | 0,10 |
| `category` | отметка МГСН табл. В.6 для категории территории | 0,20 |

Веса в `application/params.py:16-24`, профиль заменяет словарь целиком. **Разнообразие в эту
оценку намеренно не входит** (`scoring.py:1-5`): «этого вида уже много» - ограничение
назначения, а не пригодности места. Прецедент для будущей сводной оценки: оценка места и
оценка состава плана - разные объекты.

## 12. Агрегаты плана, которые уже пишутся

`plan.stats` (единственное место заполнения - `placement.py:127-137`): `alley_candidates`,
`alley_plantable`, `lawn_candidates`, `lawn_plantable`, `surface_cell_m`, `surface_cells_*`
(soil / paved / barrier / unknown), `zone_allowed_m2`, `zone_needs_approval_m2`.

`AssortmentSummary` (`assortment/summary.py:25-78`): `counts`, `genus_shares`,
`family_shares`, `conifer_share`, **`shannon`**, `decor_by_month`, `no_species`,
`quota_violations`, `existing`, `rejected_by_kind`, `rejected_by_rule`. То же отдельно по
кустарникам.

Ведомость (`application/schedule.py:66-108`): на вид - количество, стандарт, ком, **площадь
посадочных ям**. Это единственная площадь, которая уже считается по посадкам.

`green audit` (`application/audit.py:142-162`) меряет чужой план теми же правилами и даёт
`violations_by_rule` - готовая парная метрика «наш план против проектировщика».

## 13. Чего в коде нет

| Величина | Статус |
|---|---|
| Площадь крон | не считается; 10 строк, микросекунды |
| Площадь крон с учётом перекрытий | `shapely.union_all(buffer(points, r))`, десятки мс на 3 тыс. посадок |
| Погонные метры улицы | длина бортов уже вычисляется в `placement.py:222, 248`, надо положить в `stats` |
| Расстояние до ближайшей соседней посадки | не сохраняется; KDTree уже импортируется в `structures.py:18` |
| Индекс Симпсона, доля кустарников | строка рядом с `_shannon` |
| Ширина газона в точке | `distance_transform_edt` по растру покрытий; считать по bbox посадок, не по всему листу |
| Сторона борта у посадки | различима только через карту покрытий; в момент создания посадки доступа к ней нет |
| **Освещённость и тень** | **невозможно**: высот зданий в DXF нет, поле `Species.light` в коде не используется вовсе |

Мёртвые поля каталога: `light`, `moisture`, `root_type`, `growth` грузятся из
`config/species.yaml` и не используются нигде.

## 14. Куда встраивать

- Сводная оценка - в `plan.stats`: словарь уже едет нетронутым через все этапы и попадает в
  `plan.json`, `run_manifest.json` и ответ API. Добавление ключей ничего не ломает.
- Вклад отдельной посадки - рядом с `AssortmentInfo`, текст собирает
  `explain.describe_assortment()` (`explain.py:126-149`), она уже умеет раскладывать оценку
  по факторам.
- Сегодняшнее объяснение отвечает на «допустимо ли» и «почему этот вид», но ни слова не
  говорит о ценности: нет вклада в состав, роли в структуре, площади кроны и ответа «что
  будет, если её убрать».

# Нормы и каталог видов как источник метрик (22.09.2026)

## 15. Нормы, у которых есть вилка «от и до»

Это самое ценное: вилка даёт штраф в обе стороны, а не только запрет.

| Норма | Значение | Источник | У нас |
|---|---|---|---|
| **Плотность на 1 км улицы** | **150-180 деревьев и 600-720 кустарников** | МГСН 1.02-02 прил. В табл. В.1, `quotes.yaml:89-91` | **не считается** - это единственная норма, прямо отвечающая «сколько деревьев должно быть» |
| Плотность на 1 га жилой застройки | 100-120 деревьев, 400-480 кустарников | там же | нет |
| Шаг однорядной посадки | 5-6 м | 743-ПП табл. 3.6.2 | взята константа 6,0, то есть верх вилки |
| Групповая посадка деревьев | 5-7 м | `quotes.yaml:71-72` | тот же `spacing_m` |

## 17. Пары «поле вида - признак места»

Используются: солеустойчивость и газоустойчивость у дороги (полоса 5 м), крона против всех

Не используются, хотя данные есть:

- Свободный грунт вокруг ствола (норма 2,0 x 2,0 м) - карта покрытий есть, правила нет.
- `root_type` объявлен «для будущего правила о корнях у сетей».

## 18. Ловушка весов

`DEFAULT_WEIGHTS` (`application/params.py:16-24`) профиль **заменяет целиком**, а не
дополняет: фактор, не названный в профиле, получает вес ноль (`scoring.py:7-8`). Любой новый
фактор молча обнулится в старых профилях. Это надо учесть, когда появятся веса сводной оценки.

## 19. Устройство

**Гейт, а не слагаемое.** Ноль нарушений жёстких норм. План с нарушением не оценивается, а
чинится: заказчик назвал нарушение отступов причиной возврата номер один (QA:29).

**Индекс** - взвешенная сумма слагаемых, каждое в [0, 1]. Слагаемые взяты не с потолка: восемь
из десяти опираются либо на строку заказчика QA:39, либо на норму с цитатой.

| Слагаемое | Что меряет | Основание | Данные |
|---|---|---|---|
| **Плотность** | деревьев и кустарников на километр улицы против вилки 150-180 и 600-720 | МГСН В.1, `quotes.yaml:89-91` | длина бортов уже считается в `placement.py:222`, положить в `stats` |
| **Ярусность** | доля погонных метров аллеи, под которой есть ряд кустарника | МГСН 4.2.9.2 «под кронами ряды кустарника»; QA:39 «многоярусность» | координаты посадок, тип посадки |

## 20. Чем ценна конкретная посадка

Вклад посадки - насколько упадёт индекс, если убрать именно её: `вклад_i = Q(план) -
Q(план без i)`. Считается точно, а не на глаз. Это и есть ответ на «почему важно каждое
дерево», и он проверяем. **Вклады в сумме не дают индекс:** Шеннон, объединение крон и
трапеция плотности нелинейны. Для объяснения это не мешает, вопрос «что потеряем без этой
посадки» имеет точный ответ. Отрицательный вклад означает посадку, без которой план лучше
(превышение квоты, переплотнение сверх В.1): это кандидат на удаление.

Рядом с числом - человеческая расшифровка из того, что уже посчитано:

- «закрывает кроной 46 м² тротуара» - тень;
- «единственный представитель семейства в плане, держит разнообразие» - квоты;
- «пятое в ряду из двенадцати, шаг 5,8 м при норме 5-6» - структура;
- «стоит в 2,31 м от силового кабеля при норме 2,00» - запас, уже есть в объяснении;
- «газоустойчивость 2 из 2 в трёх метрах от проезжей части» - пылезащита.

Прямое основание требовать этого от нас - ТЗ:114-115: объяснение, **почему здесь нужно сажать
именно этот тип насаждения**. Сегодняшнее объяснение отвечает только на «допустимо ли» и
«почему этот вид».

## 21. Что делать в первую очередь

1. Положить в `plan.stats` длину улицы и площадь крон: два числа открывают плотность и тень.
2. Сохранять запас по каждой норме - он уже вычисляется и выбрасывается.
3. Собрать индекс как отдельный модуль поверх `plan.json`, не трогая размещение: считается по
   готовым прогонам через `tools/research/replay_assortment.py` за секунды, значит веса можно
   подобрать по всем 19 улицам сразу.
4. Проверить индекс на антипримерах, которые у нас уже есть: план проектировщика Берзарина
   (391 посадка с нарушениями из 554), наш ранний план с 26 лохами из 54 в аллее, Нижние Поля
   (18 780 посадок без границы работ). Индекс обязан назвать их плохими по разным причинам.
5. Веса и всё, что не из акта, называть параметром проекта - как уже сделано с правилом
   10-20-30.

## 22. Формулы слагаемых (черновик, веса - параметр проекта)

`Q = sum(w_k * S_k) - P`, каждое `S_k` в [0, 1], сумма весов 1, считается только при пройденном гейте.

| Слагаемое | Вес | Формула |
|---|---|---|
| Плотность | 0,15 | трапеция по деревьям на км: 0 -> 150 растёт, 150-180 единица, выше 180 падает (В.1 - рекомендуемый максимум); то же по кустарникам 600-720; деревья и кустарники пополам. Соотношение ~4 куста на дерево выходит само |
| Ярусность | 0,10 | доля погонных метров аллеи, под кронами которой есть ряд кустарника (МГСН 4.2.9.2); газонный ярус - доля стволов с незапечатанными 2 x 2 м (743-ПП п. 3.3.3) |
| Разнообразие | 0,15 | половина - между структурами: `min(1, exp(H) / D*)`, `D* = min(10, число видов, допустимых на этих местах)`, плюс запас до квот и хвойные в [0,15; 0,40] вне полосы у дороги (QA:41); половина - внутри структур: ряд = доля главного вида x доля интервалов в 5-6 м (743-ПП табл. 3.6.2), группа = величина в 2-3 / 4-7 / 10-12 (743-ПП п. 10.8.1); взвешено числом посадок |
| Пригодность месту | 0,15 | среднее `assortment.percent / 100` |
| Категория | 0,10 | доля «+» по МГСН В.6, «с огр.» - 0,5, «-» - 0 |
| Тень | 0,10 | `min(1, площадь тротуаров под union(взрослых крон) / (t * площадь тротуаров))`, `t` - параметр |
| Пылезащита | 0,10 | доля кромки проезжей части, прикрытой кронами в полосе 5 м, взвешенная газоустойчивостью вида / 2 |
| Запас до нормы | 0,10 | медиана по посадкам `min(1, m / 0,2)`, `m = (измерено - норма) / норма` по самому тесному правилу |
| Сезонность | 0,05 | половина - доля месяцев с декоративными посадками, половина - нормированная энтропия по месяцам |
| Штрафы `P` | - | доли посадок на условии, мест без вида из-за квот, слабоаллергенных; вычитаются |

Сводка плана: значения слагаемых и потолок прироста `w_k * (1 - S_k)` - куда развивать план.
Прочность весов: каждый вес +-50%, порядок улиц и антипримеров не должен меняться.
Монотонность (в тесты): вид с «-» по В.6 роняет категорию; ряд из разных видов роняет
«внутри структур»; посадка с нарушением закрывает гейт.

Сделано: `src/green/application/quality/`, подробности и числа - `docs/notes/29-quality-index.md`.
Отличия от черновика п. 22, принятые по реальным данным:
