# Презентация к финалу: план на 14 слайдов

Каждый слайд: заголовок, что на экране, что сказать, откуда число. Все числа из прогонов 18.09.2026 (`docs/notes/16-24`). Оформление и экспорт в PPTX/PDF остаются на команде.

## 1. Название

green: генеративное озеленение улиц по нормам и подземным сетям. Кейс ДПиООС, ЛЦТ 2026. Команда, дата.

## 2. Задача и что считается результатом

DXF участка (геоподоснова Мосгеотреста и сети) -> план посадок деревьев и кустарников с нормативными отступами -> DXF на отдельных слоях `GREEN_*` плюс объяснение каждой посадки и каждого отказа по пунктам актов. Приоритеты жюри в том же порядке: рабочий алгоритм, интерпретируемость, повторный прогон с другими параметрами, документация и Docker.

## 3. Что получилось за одну команду

`uv run green run улица.dxf --profile strict` или `POST /api/v1/runs`. Через 150 с (Берзарина, 206 860 сущностей): 224 дерева и 636 кустарников, 12 видов, 0 нарушений норм, ведомость с объёмами, файл объяснений, исходные 206 860 сущностей без изменений (`notes/21`, `23`).

## 4. Конвейер

Схема из `docs/algorithm.md` («Схема процесса»): чтение и ремонт DXF -> классификация слоёв (`layer_map.yaml`, все 20 улиц пилота) -> диаметры сетей из подписей -> карта покрытий (посадка только на грунте) -> кандидаты (аллея вдоль борта, сетка по газону) -> векторная проверка правил -> подбор видов с жёсткими квотами -> группы кустарников -> объяснения -> DXF -> проверка целостности.

## 5. Нормы как данные

`config/rules.yaml`: 76 правил, 46 отступов, у 75 основание сверено по тексту акта; `docs/requirements/quotes.yaml`: 84 дословные цитаты из 10 актов, скрипт находит их в текстах заказчика (81 из 81 доступных). Акты: СП 42.13330, 743-ПП (табл. 3.6.1, 3.6.2, 3.3.1, п. 3.6.18), 623-ПП / МГСН 1.02-02 (табл. В.6), 369-ПП (инвазивные), 515-ПП, СП 82, ПП РФ N 160. Нет `rule_id` - нет посадки: объяснения строятся только из трассы правил, без LLM.

## 6. Интерпретируемость

Одна посадка целиком (текст из `interpretations.csv`, Берзарина, посадка №3): расстояния до ближайших объектов с нормой, правилом и пунктами трёх актов; почему этот вид (квоты, МГСН В.6, оценка пригодности). Один отказ: «до наружной стены здания 3.37 м < 5.00 м (R-BLD-TREE-001 ...)». В DXF: атрибуты `NUM`, `SPECIES`, `NPA`, XDATA `LCT_GREEN`, легенда.

## 7. Подбор ассортимента

Жёсткие квоты 10-20-30 (вид, род, семейство), доля хвойных, существующие деревья из перечётки в квотах, категория насаждений по табл. В.6 МГСН (улицы), запреты 369-ПП и 743-ПП п. 3.6.18, колючие не ближе 2 м от дорожек (СП 82). Место, оставшееся без вида из-за квот, занимает группа кустарников. Берзарина: Шеннон 2,44, нарушений квот 0.

## 8. Нормоконтроль: сервис против плана проектировщика

Таблица из `notes/24`: посадочный план проектировщика Берзарина - 554 посадки, 391 с нарушением отступов (785 нарушений: силовой кабель 159, борт 104, опоры 77, водопровод 71), с прикорневыми барьерами 337. План сервиса - 860 посадок, 0 нарушений, 3 согласования (охранная зона ВЛ). Одна команда `green audit`, те же правила, `audit.dxf` с красными отметками и `audit.md` с пунктом акта и недобором в метрах.

## 9. Целостность исходника

`verify.json`: отпечаток каждой исходной сущности до и после, 206 860 из 206 860 без изменений, ноль добавленных вне `GREEN_*`. История: обработка однажды добавила в исходник блок стрелки (ezdxf при отрисовке выноски), проверка это поймала, исправлено, регрессионный тест (`notes/22`).

## 10. Устойчивость к реальным файлам

LibreDWG режет строки и рвёт буквы - загрузчик чинит (`notes/23`); 22 чертежа датасета объявляют миллиметры или футы при метровой геометрии - единицы решает геометрия (`notes/19`); комплект из нескольких DXF/DWG склеивается сам, несогласованный комплект называется (`notes/17`, `18`); откосы, категории, барьеры. 749 DWG датасета сконвертированы, 20 улиц классифицированы.

## 11. Параметры и повторный прогон

Профили `strict`, `no_utilities`, `barriers`, `shrubs`; любой параметр через `--set` или `overrides` в API; всё попадает в `run_manifest.json`. Пример: `barriers` даёт 350 деревьев вместо 230 (131 с барьером как условием посадки, СП 42 табл. 9.1 прим. 5).

## 12. Развёртывание

Схема из `docs/deploy.md`: один образ (Ubuntu 26.04), API на Granian и CLI, LibreDWG внутри, том для прогонов, без GPU и внешних сервисов. `docker compose up --build` и три команды проверки. Swagger `/docs`, схема `docs/openapi.json`, ошибки RFC 9457. 215 тестов, линтеры, контракт слоёв (import-linter).

## 13. Ограничения и вопросы заказчику

Не определяются по чертежу: школы и детсады (10 м), демонтируемые объекты, футляры сетей. Не сделано: групповые композиции, изгороди по контуру, CP-SAT, визуализации. Вопросы заказчику (`notes/15`, раздел 5): берёза и п. 3.6.18, величина увеличения отступа для широкой кроны, трамвай от края или от оси, токсичные виды у дорожек, неопознанные слои, назначение зданий.
