# Демонстрационный участок

`berzarina_fragment.dxf` — фрагмент чертежа улицы Берзарина из пилотного проекта ДПиООС,
окно 300 × 140 м в координатах исходного чертежа (x −2080…−1780, y 13580…13720).

## Зачем он в пакете

Кнопка «Прогнать демонстрационный участок» должна работать на стенде проверяющего, где
датасета нет. Поэтому образец поставляется вместе с сервисом, а не берётся из `dataset/`.

Синтетический топоплан, который тут был раньше, для показа не годился: на нём не видно ни
настоящей плотности коммуникаций, ни того, что сервис разбирает чужие конвенции именования
слоёв (`output[1-12]_3_ДЖКХ-24_03233up$0$Газопровод` и подобные) — а это половина задачи.

кромки покрытий, ограды, газоны, откосы, здания, существующие деревья, граница работ.

## Как пересобрать

Геометрия перенесена из исходного чертежа, а не перерисована: координаты и имена слоёв те
же. Вырезать сущности напрямую нельзя — в модельном пространстве генплана всего 95 объектов,
всё остальное лежит внутри блоков и внешних ссылок. Поэтому фрагмент собирается из уже
развёрнутой сцены загрузчиком сервиса:

```bash
uv run python tools/make_demo_fragment.py \
    "dataset/dxf/berzarina/ГП_исходный.dxf" \
    src/green/infrastructure/cad/samples/berzarina_fragment.dxf \
    --x0 -2080 --y0 13580 --x1 -1780 --y1 13720
```

Без координат инструмент печатает границы чертежа, а с `--auto` сам берёт самое плотное
место. Исходный генплан весит 95 МБ и читается около минуты; в репозиторий он не идёт.

## Ограничения

Блочная структура исходника при переносе теряется — сервису она не нужна, но это значит,
что файл не является побайтовой копией чертежа и не годится как эталон для сверки
целостности исходных слоёв. Для этого берут сам генплан из датасета.
